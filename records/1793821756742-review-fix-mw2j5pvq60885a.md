## spec proposals

- `require_platform` (`skills/client-core/modules/unit-test-core.md:229`, `## DEV`): change the output from `none` to "whether the test goes on: `false` when the current platform is not in the list (that test is recorded as skip), `true` otherwise", and add to `### run and result file` the rule "a test returns right after `require_platform` gives `false`". Reason: in GDScript a called function cannot stop the function that called it, and GUT awaits the test function (`addons/gut/gut.gd:622` `await script_inst.call(test_name)`) with no way to cancel it. So the runner cannot "end that test" while its body goes on (see R1-1 in `## review`). Every current caller already writes its own guard right after the call (e.g. `client/godot/core/sound_core/tests/test_limiter.gd:32`, `client/godot/core/auth_core/tests/test_plugin_waits.gd:121`, `client/godot/core/unit_test_core/tests/test_page_input.gd:45`). With a return value, the guard would test that value instead of repeating the platform list, and the rule would be written down

## review

- R1-1: disputed for the runner part. Evidence: GDScript has no way for `require_platform` to stop the rest of its caller's body. A runtime error ends only the function where it happens, and `return` returns only from `require_platform`. GUT runs a test as `await script_inst.call(test_name)` (`addons/gut/gut.gd:622`) and cannot cancel that await. So when a body after the call waits on a signal that never fires, no later test can run: neither GUT nor UnitTestCore can move on to the next test. The runner already ends such a run with a run failure (`_on_test_not_returned`, `client/godot/core/unit_test_core/dev/unit_test_core.gd:526`). The fix the review offers for this case is the spec change in `## spec proposals`, and the tool counted this finding as `spec change: no`, so I did not make that change. The part that code can do is tested: a skipped test stays `skip` whatever its body does after the call. An assert failure or an unchecked error log after the call does not change it, because `_record` (`unit_test_core.gd:478`) checks `skip_reason` first and `_finish_test` (`unit_test_core.gd:677`) reports no failure for a skipped test. Added sample `test_requires_another_platform_then_fails` (`client/godot/core/unit_test_core/tests/resources/sample_platform.gd:11`) and its checks in `test_require_platform_skips_a_core_test_and_fails_a_regression_test` (`client/godot/core/unit_test_core/tests/test_run.gd:315`): `skip` with no run failure in a core run, `fail` in a regression run
- R1-2: fixed. `client/godot/core/unit_test_core/dev/unit_test_core.gd:136`: `_init_failure` now fails `init` with an error log when `UnitTestCore.startTimeLimitMs` is missing, is not an integer, or is below 1. Test `test_init_fails_with_an_error_log_without_a_start_time_limit_of_1_or_more` (`client/godot/core/unit_test_core/tests/test_lifecycle.gd:61`) covers three cases: the key removed from the settings file values, a string value, and 0. In each case `init` is `false` with exactly one `UnitTestCore` error log, `init: core setting UnitTestCore.startTimeLimitMs must be an integer of 1 or more`. This test fails on the code before the fix, because `init` succeeded there
- R1-3: fixed by adding tests in `client/godot/core/unit_test_core/tests/test_host_failures.gd`
  - `test_requests_a_test_host_refuses_give_the_failure_value_and_one_error_log` (line 7) uses a loopback HTTP server as the test host. That server answers 404 to every path without a registered response, and 500 to `/input`. The test checks `POST /servers` → `""`, `PUT /responses` → `false`, `GET /requests` → empty list, `POST /ws-servers` → empty URLs, and `POST /input` with 500 for both `put_page_click` and `put_page_key` → `false`. After each call there is exactly one `UnitTestCore` error log, and the refusing server recorded each request path in order
  - `test_page_key_with_an_empty_key_is_false_with_an_error_log` (line 39): `put_page_key("")` is `false` with one `UnitTestCore` error log
  - Mutation check: I removed the empty-key error log and the `_host_failure("POST /ws-servers", ...)` call, and those two tests failed. The mutation is reverted and not committed
