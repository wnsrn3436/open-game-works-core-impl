## review

- R1-1: fixed.
  - `server/core/routing/front_link.ts`: new `ToFront` message `pull` and the `Inflow` class (front_link.ts:70-99). `FrontRequest` and `BridgeSocket` push each `data` chunk with `Inflow.take`, and they pull its bytes (send `pull` to the front) only when `push` stays under the high water mark or when the stream reads again (`_read`). A request that does not read, or that stopped reading (`read_body` pauses at `routing.maxBodyBytes` / `routing.bodyReadTimeoutMs`), pulls nothing. `FrontResponse.end` removes the request from `requests`, so `data` after the answer is dropped (front_link.ts `start`, `receive`)
  - `server/core/routing/server_process.ts`: `send_data` counts the bytes in flight per handed request or upgraded connection and pauses the client stream at `FRONT_WINDOW_BYTES` (64 KiB); a `pull` resumes it (`from_worker`). The request `data`/`end` listeners send only while the request is still handed. When the answer comes before the body has ended (`!req.complete`), the front writes it with `Connection: close` (`closing`), so Node closes the connection after the answer and does not read the rest. The same window applies to the bytes of upgraded connections
  - tests: `server/core/routing/tests/front-link.test.ts` `front link flow` (pulls only taken bytes, none while not reading, no buffering after the answer); `server/core/routing/tests/server-process.test.ts` `closes the connection after an answer that came before the end of the body, and stops reading that body` (a 1 GiB `Content-Length` POST to an unknown path gets 404 with `Connection: close` and the connection closes before the body is sent; a normal request on the process still works)
- R1-2: fixed. `server/core/routing/pipeline.ts:865`: `Pipeline.upgrade` with no route writes `HTTP/1.1 404 Not Found` with `Content-Length: 0` and `Connection: close` and ends the socket, with no `request` log. Test: `server-process.test.ts` `with --matchmaker ...` now expects `HTTP/1.1 404` from a server process without `--matchmaker`, and not 404 from the realtime worker
- R1-3: fixed before this job, in commit 54fa46c3 (main), which was made for review `cheat` R1-1. `server/core/routing/dev/index.ts:167` calls `pipeline.process_tokenless(exchange, entry.info, handler, validate)`, and `process_tokenless` (`pipeline.ts:529-535`) always runs `check_min_version` after the IP counter; the comment now says "A token-less core `rpc` or `DevLogin` ... the minimum app version judgement of step 7". Test: `server/core/cheat/tests/processing.test.ts` `answers DevLogin below min_version with APP_UPDATE_REQUIRED without the auth handler, and skips step 7 for the other cheats`, which passed in this job's `ogw core test server routing testing cheat`. No change in this job
