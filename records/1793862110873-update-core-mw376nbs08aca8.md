## spec proposals

- `## test` of matchmaker.md, item "On PostgreSQL, when a participant whose connection closed sends `MATCH_REJOIN` on a new connection while `testing.hold_lock_key` holds the lock of that match record row, and after `MATCH_REJOINED` sends `MATCH_LEAVE` and closes that connection before `release` ...": the lock wait of `storage.lock_game_row` blocks the server's thread, and in core tests that is also the test's thread. So no frame can be sent or handled while a game transaction waits for that lock. The test therefore gates the `REJOINED` transaction before it starts, sends `MATCH_LEAVE` and closes, and only then lets that transaction wait for the held lock (`hold_until_waiter` releases it once it waits). Proposal: write the item without requiring frames to be handled during the lock wait itself, e.g. "while the game transaction of that `REJOINED` has not ended". The same holds for "When the write of a `DISCONNECTED` waits for the match record row lock" (also tested with the gate)
