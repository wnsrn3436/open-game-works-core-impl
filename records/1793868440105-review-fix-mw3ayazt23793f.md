# review fix coupon round 4

## done

- coupon: `lock_use_row` (`server/core/coupon/index.ts:369-373`) no longer writes its own `error` log. It still returns `INTERNAL` on a `FAILED` step 4 lock, and the broken transaction makes `routing` step 13 write the one `error` log
- storage: the `## out of scope` defect of round 4 (`server/core/storage/tx.ts` `run_user`, `run_game`), fixed together with R4-1 as the review's fix asks, because without it no `error` log would be written at all. `body` (`server/core/storage/tx.ts:190-208`) now follows `storage.md` `### transaction`: when a statement, `lock_game_row` or a lock step broke the transaction, a function that ends by return (any value, also a failure code, also in a rollback transaction) or by a throw of another value makes the operation `FAILED`; a function that throws the value of the statement failure that broke it rolls back and throws it. `TxState.broken_by` (`server/core/storage/core.ts:127-128`) keeps that value, and `mark_broken` keeps the first one. This applies to `run_user_transaction`, `run_request_transaction`, `run_rollback_transaction` and `run_game_transaction`
- Tests of other modules that relied on the old storage behavior, changed to the spec:
  - friend `server/core/friend/tests/lock-timeout.test.ts` `while_held`: on PostgreSQL, the request adds exactly one `error` line, routing's `request transaction failed` with that request name (friend spec `## error`: "`routing` leaves an `error` log"; auth spec `## error` row of `remove_user` `FAILED` in `Withdraw`: "`error` log by `routing` (step 13)"). Before, it matched friend's thrown message, which routing logged as an unhandled exception
  - guild `server/core/guild/tests/locks.test.ts` "makes lock_guild of the module object FAILED past the lock wait limit (PostgreSQL)": the handler that returns `REJECTED` after a `FAILED` `lock_guild` now gets `INTERNAL` (`storage.md` `### transaction`, `routing.md` step 13)
- Runs: the last `ogw core test server` over storage, coupon and every module that `ogw core dependents storage coupon` lists on the server side (41 modules), all `pass` on SQLite and PostgreSQL. `ogw code check core`: type check, lint, dependency, secret all `pass`
