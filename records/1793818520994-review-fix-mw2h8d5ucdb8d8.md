# review fix BootstrapCore round 1

## done

- `BootstrapCore` (Godot): `start_boot` now records the boot entry scene in every boot, not only when the module list is omitted (`client/godot/core/bootstrap_core/bootstrap_core.gd:178`, `_find_boot_entry_scene` at :187). The boot entry scene is `SceneTree.current_scene` when its `scene_file_path` is the project main scene (`application/run/main_scene`). A boot whose `BootTestReplacements` are kept has none, because a test or `UnitTestCore` started it, not the boot entry scene. Core test state `_test_main_scene_path` (:141) replaces the main scene path in tests. Boot test support sets it in `prepare`, so the main scene of the browser run (the test runner scene `res://ogw_web_runner.tscn`) is never taken as the boot entry scene
- `shutdown` now writes its module `release` calls to the core test trace (`bootstrap_core.gd:1323`) the same way reverse release does (:1215), so a test can check their order
- Test support: `open_entry_scene`, `close_entry_scene`, `hold_update` (a build info with a deploy list URL, and a `GameUpdateCore` whose downloader waits until `cancel`, `tests/support/boot_test_held_downloader.gd`), `releases`, `reverse_releases`
- Runs: `ogw core test godot BootstrapCore QACore UnitTestCore` and the same with `--web` both pass (the dependents from `ogw core dependents BootstrapCore`). `ogw code check core` passes all four checks: type check, lint, dependency, secret
- No engine-specific implementation rules document or `## <engine> build` of `tools/ogw.md` was written

## spec proposals

- `client-core/engines/godot.md`: no line states how Godot identifies the boot entry scene. Proposed line: "The boot entry scene is `SceneTree.current_scene` at the `start_boot` call when its `scene_file_path` is `application/run/main_scene`. A `start_boot` that keeps `BootTestReplacements` has no boot entry scene." The implementation follows this rule now. Without the line, the browser test run is exposed: its main scene is the test runner, so taking `current_scene` alone could free the runner
- `bootstrap-core.md` `## test`: add an item for the `TitleScene` behavior "On success, destroys the boot entry scene", e.g. "When the boot entry scene is the current scene, it is destroyed after `boot_change_scene` of `TitleScene` succeeds, and it remains when it fails". The new tests check this, but no `## test` item names it
