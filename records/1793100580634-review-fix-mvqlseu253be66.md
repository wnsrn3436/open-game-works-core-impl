# review fix storage

## done

- `storage` `sweep_expired` (server/core/storage/rows.ts:381-412): after a delete statement that deleted `storage.sweepBatchSize` rows, the loop awaits one event loop turn (`next_turn`, `setImmediate`) before it reads the table budget signal of `network_time_limit`. The budget is still measured only with `network_time_limit`, as server-time.md:89 and the core static check require (a first try with `performance.now()` was rejected by the static check: `system clock: performance.now() outside the clock adapter`). The yield also lets other requests of the server instance run between statements of a long sweep on SQLite.
- Tests in server/core/storage/tests/expiry.test.ts (`sweep_expired batches`):
  - `one delete statement deletes at most storage.sweepBatchSize rows, and storage.sweepTableBudgetMs passed after a statement stops that table only`: batch size 2, 5 + 3 expired rows in two tables, a budget signal that has already aborted (a `vi.mock` of `network_time_limit` that returns `AbortSignal.abort()` only for the sentinel budget `PASSED_BUDGET_MS`). The runs delete 4 (2 per table), then 3, then 1.
  - `with storage.sweepBatchSize 1 and storage.sweepTableBudgetMs 1, one sweep_expired deletes fewer than the 2000 expired rows of a table, and later runs delete the rest`: uses the real timer, no mock.
- `ogw core test server` for storage and every server module from `ogw core dependents storage`: all pass, on both SQLite and PostgreSQL. `ogw code check core`: all checks pass.

## spec proposals

- server-core SKILL.md:32 says "the only files that use timers are `scheduler.ts` and `network_time_limit.ts`". `setImmediate` is in Node's timers API but is not a time-based timer, and the static check (`TIMER_CALLS`) does not flag it. I used it in `storage` only to give up the event loop turn so a `network_time_limit` signal can fire. Proposal: state in that line that a `setImmediate` yield (no delay) is allowed outside those files, or add a server-time operation for that yield. Otherwise, if the rule is meant to cover `setImmediate`, the static check should list it and `sweep_expired` needs another way to give up the turn.
