## spec proposals

1. In a browser, a real SDP refusal probably does not raise peer lost. `_godot_js_rtc_pc_remote_description_set` in the 4.7.2 web template (`web_nothreads_debug.zip`, `godot.js`) refuses in a promise after the call returned, so the transport gets no error value. The spec line "`connect_peer` fails ... when the connection refuses a received SDP" and its `## test` line hold in the browser run only through the test seam. The participant there would wait for the time limit, as before this change. Recommendation: state in the spec that this failure is only detected where the engine returns it, unless the engine error callback can be reached. What the engine's native error callback does after that promise was not read.
2. The waiting branch of `RealtimeCore.leave_room` calls transport `leave_room` and not `close`, also in `None`. A `MATCH_FOUND` read in the same `poll` is then discarded with the transport still holding that match, which is the leak item 8 fixes for `_leave_room_now`. The input names only `_leave_room_now`, so it was not changed. Recommendation: the same `close` in that branch.
3. A non-host member that gets `MATCH_FAILED` and `MATCH_FOUND` in one `poll`: the `close` of the failure already sent `MATCH_LEAVE` of that match and reset the transport, since the transport reads frames before RealtimeCore handles notices. The spec now handles that match found in `None`, so the member goes to `Connecting` with no connections and fails at the connect time limit. Before this change it was discarded. It needs the next entry to be found within one frame of the failure. Recommendation: decide whether the spec keeps this outcome.
