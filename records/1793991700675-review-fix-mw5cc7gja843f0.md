## review

- R1-1: fixed. `client/godot/core/qa_core/dev/qa_core.gd:1241` (`_apply_module_states`) and `:1251` (`_wanted_state`). Behavior is unchanged. The existing tests in `tests/test_feedback_switch.gd` check the module states for feedback off, the reward window, both together, and release, and they pass. No new test was added for this finding: a literal that is created and freed inside one call leaves nothing behind, so godot `## test` says a memory test cannot catch it, and that it is judged by reading the code against the frame code rules
- R1-2: fixed. Added `test_putting_intervals_into_a_full_record_allocates_no_memory` (`client/godot/core/qa_core/tests/test_frame_interval.gd`). It fills the record to its `QACore.frameIntervalMaxCount` size with `QACore._record_frame_point`, calls `LogCore.release`, runs 100 warm-up calls, then reads `Performance.OBJECT_COUNT` and `MEMORY_STATIC` before and after 1000 measured calls. It asserts that neither value grew and that the record kept its size and stayed full
