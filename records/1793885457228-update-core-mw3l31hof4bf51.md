# update core: QACore

## done

- module: `QACore` (Godot), commit 23cf264. Follows the QACore spec diff 2e8185b..HEAD of the harness. The godot.md diff changes no QACore row
- An input command (the commands marked input in the built-in command table, `INPUT_COMMANDS` in `qa_builtins.gd`) that has not ended at its time limit no longer fails right away. `QACore._time_out_input` (`client/godot/core/qa_core/dev/qa_core.gd`) does three things. It drops that command's device inputs that have not gone in yet. At the next frame start it puts in a release for the touches, keys, mouse buttons and gamepad buttons the command holds, and 0 for the gamepad axes it set that are not 0. It fails the command when that frame ends. What a command holds is recorded per command when its inputs go in (`qa_command.gd` `holds`, `qa_input.gd` `apply_own`; a move by a command that did not press that touch does not count as holding it). The release counts as the command's device input, so in step mode it gets the 1 ms step budget, and `_finish` sets the budget left back to 0
- `_cut` in `qa_builtins.gd` now also counts `timed_out`, so a timed-out input command puts in nothing of its own. `_end_after_input` and `text` check `_cut` again after the frame end, so the command does not succeed in the frame where its time limit puts in the release. The `or command.done` branches in `drag` and `key` are removed: before, they put in a move to the end position and then a release after the time limit
- A cheat command whose `NetworkCore.send_cheat` ends with `false` ends with `result` `the cheat request failed` and leaves no QACore warn log (new `warn` argument of `QACore._finish`). Cheat argument failures that happen before any request still leave a warn log
- A command ends once. Content handlers, `send_cheat` and the other awaited operations already checked `done`/`_gone` and made no second response. New tests now check this
- tests:

  - `test_cheats.gd`: `test_a_rejected_cheat_fails_without_a_qa_core_warn_log`, `test_a_cheat_over_the_time_limit_ends_once`
  - `test_commands.gd`: the time-limit test also checks that no log comes from the late handler and that the last command result stays the same
  - `test_channel.gd`: `test_a_command_ended_by_its_time_limit_answers_once` (content handler and `send_cheat`, no second response)
  - `test_setup.gd`: `test_force_network_failure_fails_the_requests_until_none` now expects no QACore warn log for a cheat whose `send_cheat` ended with `false`
