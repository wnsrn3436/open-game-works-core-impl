- R1-2: fixed. index.ts:150–157 builds a `Map` from one `list_state` result, made lazily at the first in-window mission, and looks up each mission's row there before the round reset and lazy reset. Each mission of a counter appears once in `missions_of`, so a row written in the loop is never read again from the map in the same call. A later `add_progress` (e.g. from `on_mission_claimed`) runs its own `list_state` and sees the earlier writes of the transaction. The existing progress, reset and `on_mission_claimed` delta tests cover this behavior and pass
