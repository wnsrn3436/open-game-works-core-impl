# review fix UnitTestCore round 1

## done

- UnitTestCore (Godot): test setup (`_setup_test`) and the run end (`_close_run`) now call `_clear_pre_init_values` right after `BootstrapCoreDev.shutdown()`. When TimeCore is not initialized it calls `TimeCore.release()`, whose `_reset` clears the random base and frame step that `TimeCoreDev` keeps from before `init` until `release`. The test clock it also clears is registered again by `_register_replacements` (test setup, `_pop_run`) or taken back by `_unregister_replacements` (run end)
- No engine-specific implementation rules document was written. `## <engine> build` of `tools/ogw.md` was not written

## spec proposals

- `### test setup` of skills/client-core/modules/unit-test-core.md step 1 says to "`release` all modules with `BootstrapCore.shutdown`", but `shutdown` releases only initialized modules. So DEV values a module keeps from before its `init` until its `release` stay in the next test when that test never reached `init`. Proposal: add a step that clears the pre-init DEV state of modules that are not initialized, or have `BootstrapCore.shutdown` in DEV runs call `release` on modules that are not initialized. Modules that keep such values besides TimeCore (from their doc comments, not reproduced): DataCoreDev data location, AuthCoreDev DEV token storage, GameUpdateCoreDev downloader, NoticeCoreDev image downloader, ResourceCore core-test hooks, AccessibilityCore test rendering method. NetworkCore transport and the LogCore/TimeCore test clock are re-set by replacement registration. This fix covers only TimeCore, the module the finding named
