## review

- R1-1: disputed. The finding is real (the reviewer's run path gives 3 `_process` calls before stage 7), but it cannot be fixed in code without breaking another rule of the same mapping. Evidence:
  - `godot.md:291` (scene holder row) says hiding and disabling are done right after the `add_child()` of stage 4 and on `SceneTree.node_added` until stage 7, and "SceneCore reads `visible` and `process_mode` only at those times". The code does exactly this: `scene_core.gd:308`–`:313` (stage 4 `add_child()` then `_hide_tree`), `_stop_if_own_mode` (`scene_core.gd:664`) and `_on_node_added` (`scene_core.gd:731`). R2-2 (`fixed` in round 7) asked for the removal of the per-frame check so that the code follows that sentence
  - In Godot, `Node.can_process()` uses the node's own mode when it is not `PROCESS_MODE_INHERIT`, so a node under the `PROCESS_MODE_DISABLED` holder processes as soon as scene code gives it `PROCESS_MODE_ALWAYS` or `PROCESS_MODE_PAUSABLE`. The engine tells no other object that a node's mode changed: `NOTIFICATION_ENABLED` goes only to that node, and `SceneTree.tree_process_mode_changed` is emitted only in the editor (measured on the pinned Godot 4.7.2 in round 4: 0 emits after 3 mode changes, `records/1793828151773-review-fix-mw2mysbhaddf32.md`). So SceneCore can stop this node only by reading `process_mode` at some other time, which `godot.md:291` forbids, and even the removed per-frame check did not catch a mode given inside the `_process` of an earlier node in the same frame (round 4 measurement)
  - The other writes SceneCore could make (`set_process(false)`, `set_physics_process(false)`, the input variants, on every node) are not in the mapping, so `## rules` forbids them. They would also not close the case: Godot turns processing back on in `NOTIFICATION_READY` for a script with `_process`, which comes after `node_added`. Scene code can call `set_process(true)`, and `Timer.start()` and `AnimationPlayer` use internal processing, which those calls do not stop
  - So the mapping sentence "SceneCore reads `visible` and `process_mode` only at those times" and the sentences "does not receive the per-frame engine callbacks" (`scene-core.md:47`) and "`_process()`, `_physics_process()` ... do not run" (`godot.md:291`) cannot all hold for this case. The proposal is in `## spec proposals`
