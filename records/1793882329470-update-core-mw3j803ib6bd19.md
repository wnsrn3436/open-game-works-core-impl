# update core: UICore

## done

- Module `UICore` (Godot) now matches the current spec (harness `2e8185b..HEAD` of `ui-core.md` and the UICore rows of `godot.md`). Commit `280d32e` on branch `agent/mw3j803ib6bd19`.
  - `UISystemPopup` (`client/godot/core/ui_core/ui_system_popup.gd`, `class_name UISystemPopup`, `extends UIPopup`, `@export var body_area: Control`, `@export var button_area: Control`). `_build_system_popup` passes those areas to the view when the `UICore.systemPopupResource` root is a `UISystemPopup` and the area is the root or a node inside it. `system_popup_view.gd` fills the root. It puts the scroll area under the body area `Control` and the button row under the button area `Control`, each filling it. An area taken from the root is a child of the view: the button row is a strip along the bottom edge. The body sits above the top edge of the button area, and follows the button area `Control` when only that one is set.
  - Open and close tween presets load into the object scope (kind `TweenCore.get_preset_kind`) right after the panel or popup object is created and before `accepts_param` (`_make_view`, `_popup_open_flow`). A system popup shows only after that load. While loading it is kept in `_loading_system`, outside the tree. That list counts for `is_flow_in_progress` and back step 1. `close_all_popups` cancels it (`false`, no hidden callback), and `release` frees it.
  - System popups stack in `open_system_popup` call order (`_POPUP.order`, `_show_system_record`), also when a later call's tween presets finish loading first.
  - `reset_panel_stack`: closing a panel at once stops its open or close tween (`_VIEW.tween_handle`, `_close_view_now`). A panel that already got `on_closed(Closed)` in close flow step 5 does not get it again (as before).
  - Back step 4 also ignores back input while the queue is not empty. This covers the moment between the `Opened` result of one popup and the start, in the same call, of the next queued popup's open flow.
  - `UIScrollList.append_items` and `prepend_items` called while a `set_items` waits now add to that `set_items`'s item count, return `true`, and bind nothing. A newer `set_items`, or one that ends with `false`, drops those items.
  - `PanelFlowFinishedEvent` no longer has `panel_key`. The close flows no longer set the now-unused `flow.panel_key`.
  - These rows already matched the spec and were kept: event order closed, opened, `PanelFlowFinishedEvent`, including a transition started from a `UIOpenedEvent` subscriber; `close_popup` order (hidden callback, `UIClosedEvent`, after-close); the error rows on prefab roots that are not panels or popups and on `accepts_param`; a close flow that skips a non-panel destination, including the root item, and ends with an empty stack; `open_panels` replacing an item that is not the root item.

## spec proposals

- `UISystemPopup`: the spec does not say what happens when `body_area` or `button_area` points to a `Control` outside the prefab (e.g. a node path that resolves outside the root). The implementation treats such an area as none (taken from the root) and leaves no log. Proposal: state this in the system popup area rule, or add an error row if a log is wanted.
