# update core: MessageCore

## done

- Module `MessageCore` (Godot), commit `fdce54d` on `agent/mw32h7ze4b53f7`. Changes in `client/godot/core/message_core/message_core.gd`:
  - Toast object cannot be borrowed: MessageCore no longer logs. `PoolCore` or `ResourceCore` writes the log. An empty handle from `PoolCore.borrow` is not passed to `PoolCore.get_instance`, so that one failure gives one log and not two (`get_instance` before init logs again)
  - Borrowed toast object destroyed outside while on display: MessageCore no longer logs (`PoolCore` writes it). Toast object made by code or black box object destroyed outside: MessageCore logs one error. This log now comes from `_drop_destroyed`, so it is left when the frame check finds the destruction and also when a kind close (`close_black_box`, `close_all`, the close of a second `prepare`) or `release` finds it first. Before this change a kind close or `release` dropped it with no log. No request of the queue is shown after such a close. A destroyed borrowed toast object is not given back in 5, a kind close or `release` (the code already did this; tests now cover it)
  - Display step 1 for an object made again (toast made by code or black box object destroyed outside and made again in 1): its tween property values are recorded when it is made, so the reset uses the values of that object when it was made
  - Displayed text vs. wording: the code already checked the empty wording before appending the extra text and compared displayed text for the same-text rule; tests added
  - D1: `_load_preset` returns the definition and the failure is separate from the length, so a preset with a negative repeat count (or negative delay or duration) no longer makes `prepare` fail with no log. Such a preset loads and does not repeat forever, so by the `## error` table `prepare` is not a failure. `TweenCore` rejects it at playback with its definition check log
- No change from `godot.md`: the only MessageCore part of the diff is the UI component row, where `UISystemPopup` was added and `MessageView` is unchanged
- Tests added: `test_close.gd` (borrowed toast destroyed during the enter tween and during 3: one `PoolCore` error and the next toast shows; toast made by code destroyed during 3: one MessageCore error and the next toast shows; `close_all` in the same frame as the destruction of the toast made by code with a queued request: one MessageCore error and no toast; `close_all` in the same frame as the destruction of a borrowed toast: no give_back, only the `PoolCore` destruction error; `close_black_box` with a destroyed black box object: one error and no block; `release` with both destroyed: one `PoolCore` and one MessageCore error, no give_back), `test_text.gd` (same wording with different extra text both show; empty wording with extra text is ignored with one error), `test_display.gd` (toast made by code after an exit tween to opacity 0 shows with the opacity it was made with), `test_view.gd` (D3: center of the displayed text of the toast made by code), `test_prepare.gd` (D1: preset with repeat count -1, new resource `tests/resources/test_fade_negative_repeat.tres`). Updated `test_close.gd` borrow-failure and destroyed-object tests to the new log owners (exact `PoolCore` counts, MessageCore 0)
- Last runs: `ogw core test godot` and `ogw core test godot --web` over MessageCore and the modules `ogw core dependents MessageCore` lists (20 client modules). Web run: all 20 pass. Headless run: 19 pass, and `QACore` was `skipped` because its render pass did not run (macOS screen locked or display asleep). `ogw code check core`: type check, lint, dependency and secret all pass

## spec proposals

- `skills/client-core/engines/godot.md`: write the Godot value of the `PoolCore` empty handle (`Vector4i.ZERO`). MessageCore now compares the `borrow` result with it, so that a failed borrow gives only the `PoolCore` log. Today that value is only in the `PoolCore` class comment. The alternative is a spec line in `pool-core.md` that `get_instance` of an empty handle leaves no log before `init` either
- `message-core.md` `### prepare`: the length of a tween preset that loads but fails the `TweenCore` definition check (negative repeat count, negative delay or duration) is not settled. The formula cycle time × repeat count gives a negative or wrong value, but `TweenCore` plays such a preset with no steps, so its real length is 0. The implementation uses the formula as written. Proposal: the length of a preset that fails the definition check is 0. This would need a way for MessageCore to judge it; `TweenCore.check_definition` has only `ScreenEffectCore` as caller
