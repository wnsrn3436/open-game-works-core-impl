## spec proposals

- **Godot rule for the engine fps of the frame step does not work on the pinned Godot (`skills/client-core/engines/godot.md`, row `TimeCore` / engine at a fixed frame rate).** On Godot 4.7.2.stable, the engine consumes `--fixed-fps` itself, and `OS.get_cmdline_args()` does not return it. I checked this by running the pinned binary:
  - `godot --headless --fixed-fps 25 --script …` gives `OS.get_cmdline_args()` = `["--script", "res://probe2.gd"]`
  - `godot --write-movie out.png --fixed-fps 30 …` gives a non-empty `Engine.get_write_movie_path()` but `editor/movie_writer/fps` = 60, not 30
  - Effects:
    - `--fixed-fps` without Movie Maker never gives a frame step
    - With Movie Maker, the frame step is the project setting fps, not the recorded fps. The runner (`tools/src/commands/instance/lib/launch.ts` `clientLaunch`) passes `--write-movie … --fixed-fps <movie.fps ?? 60>`, so the result is right only when that fps is 60, the project setting default
  - The implementation follows the rule as written. Proposal: the runner also passes the fps as a user argument, e.g. `-- --fixed-fps=<fps>`, and the Godot rule reads it from `OS.get_cmdline_user_args()`. Alternative: a launch value that `BootstrapCore` passes to `TimeCoreDev.set_test_frame_step` before `init`. Keep the Movie Maker setting as the fallback
- Precedence is not defined when both `set_test_frame_step` and an engine fixed fps are present. Implemented: the `set_test_frame_step` value wins. Proposal: the spec should state this
- An invalid `--fixed-fps` value is not covered: it can be missing, not an integer, or below 1 (Godot uses `-1` to turn it off). Implemented: no frame step, with no fallback to the Movie Maker fps even when a movie path is set. Proposal: the Godot rule should say whether an fps < 1 counts as "there is none" and falls back to Movie Maker
