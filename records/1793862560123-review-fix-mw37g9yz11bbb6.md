# PaymentCore review fix (round 4)

## done

- Module `PaymentCore` (Godot client core), commit b9d6e7b on `agent/mw37g9yz11bbb6`
  - A run whose login session ended stops before its next step:
    - `recover_purchases` and `restore_purchases` stop before `list_unfinished` and `list_owned`
    - the subscription sync is not sent
    - `purchase` stops after the guest warning and after `prepare`
  - `recover_purchases` and `restore_purchases` are shared only within one login session. A change of login session lets go of `_recover_wait` and `_restore_wait`, so the next call starts its own run. The old run clears the shared slot only when it still holds its own wait
  - `_in_flight` now holds only the transactions of the current login session: it is emptied on a change of login session, as `in-flight transaction` of the spec defines (`:157`). The two cross-session tests listed under R4-5 need this. Without it, a transaction that a run of the ended session is still processing is skipped in the new session
- `tests/support/hanging_store_adapter.gd`: a released `connect` now returns `false` when `fake_set_fail(connect, true)` is set, so the `StoreFailed` path of R4-3 runs in a test. The existing time-limit test does not set it and is unchanged
- No engine-specific implementation rules document. `## <engine> build` of `tools/ogw.md` was not written
- Tests:
  - `ogw core test godot` and `--web` for PaymentCore, AdCore, BootstrapCore, QACore and UnitTestCore all pass. The native run exited 1 only because QACore was `skipped`: its render pass did not run because the screen was locked
  - `ogw code check core` passes (type check, lint, dependency, secret)
  - With the old `payment_core.gd` restored temporarily, every new test that targets R4-1, R4-2, R4-3, R1-8 or R1-10 failed. The R4-4 tests and the `:282` test passed on the old code, as the review expected
- `ogw core test` regenerated `core-spec/routing.json` (`storage.userLockWaitMs`) from the harness specs. That change is not part of this fix and was not committed
