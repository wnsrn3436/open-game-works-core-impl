## spec proposals

- R1-1 (mode that scene code gives an already added node before stage 7): the scene holder mapping of `skills/client-core/engines/godot.md` says SceneCore reads `process_mode` only right after the `add_child()` of stage 4 and on `node_added`. `scene-core.md` (scene holder) says the scene "does not receive the per-frame engine callbacks", and the mapping says "`_process()`, `_physics_process()` ... do not run". A node under a `PROCESS_MODE_DISABLED` holder whose own mode scene code sets to `ALWAYS` or `PAUSABLE` processes in Godot (`Node.can_process()` takes the node's own mode when it is not `INHERIT`). Godot has no signal that tells another object when a node's `process_mode` changes (`NOTIFICATION_ENABLED` goes only to that node). So no code that follows the mapping can stop this case. Proposal: add one sentence to the mapping of `godot.md`, for example: "Scene code does not set a `process_mode` other than `PROCESS_MODE_INHERIT` or `PROCESS_MODE_DISABLED` on a node that is already under the holder before stage 7. A node with a mode of its own is added with that mode. A mode set otherwise takes effect at once, and stage 7 still gives back the remembered mode." The other choice is an exception in `scene-core.md`. The choice is the lead's or the human's

## review

- R6-1: fixed. `_restore_stopped` (`client/godot/core/scene_core/scene_core.gd:708`) sets the remembered mode without reading `process_mode`, and `_stopped` keeps one mode per node (`scene_core.gd:67`, `:664`). Test `test_remembered_node_gets_its_remembered_mode_back_at_stage_7` (`client/godot/core/scene_core/tests/test_scene_holder.gd:135`) covers four cases. (1) A resource node (`ALWAYS`) set to `PAUSABLE` gets back `ALWAYS`. (2) A node added with `PAUSABLE` and set to `ALWAYS` gets back `PAUSABLE`, which is the reviewer's run path. (3) A node set to `INHERIT` gets back `ALWAYS`. (4) A node removed, given `WHEN_PAUSED` and added again is disabled at `node_added` and gets `WHEN_PAUSED`. A remembered node freed before stage 7 leaves no error
- R6-2: fixed. `client/godot/core/scene_core/tests/resources/scene_b.tscn` has `Hidden2D` (`Node2D`), `HiddenLayer` (`CanvasLayer`) and `Hidden3D` (`Node3D`) with `visible = false`, one for each condition of `_hide_if_top`. `test_node_hidden_in_the_scene_resource_is_still_hidden_after_the_transition` (`test_scene_holder.gd:57`) asserts they are hidden after `started:` while `Probe`, `Layer` and `Spatial` are visible. `test_node_that_on_prepare_hides_is_visible_after_stage_7` (`test_scene_holder.gd:79`) hides `Probe`, `Layer` and `Spatial` in `on_prepare` and asserts they are visible after `started:`
- R2-2: fixed. Removed `client/godot/core/scene_core/stop_check_node.gd` with `_watched`, `_watching`, `_set_watching`, `_check_stopped`, the call after `on_preload` and the `node_removed` connection (`scene_core.gd`, `scene_core_node.gd`). Nothing under SceneCore runs per frame on the nodes of the new scene. Tests: `test_nodes_with_a_process_mode_of_their_own_run_frames_only_after_stage_7` (`:101`) and `test_node_added_by_a_handler_of_the_stage_4_hiding_runs_frames_only_after_stage_7` (`:182`). The second one now also checks that a visual node added from the stage 4 hiding handler is hidden, then visible after stage 7. The removed/freed hiding tests (`:220`, `:224`) now check that the walk skips the node and that a later added node is still disabled. Removed the tests of the stop check node and of the modes given after a node was added: `test_nodes_that_process_first_and_get_a_mode_during_stage_6_...`, `test_stop_check_runs_only_...`, `test_stop_check_ends_when_the_transition_ends_with_false`, and the `given` and `later` counters
- R1-1: disputed. Evidence: the round 6 mapping (`godot.md`, scene holder row) says "SceneCore reads `visible` and `process_mode` only at those times" (stage 4 right after `add_child()`, and `node_added`). R2-2 asks for code that follows that sentence. With such code, a node already under the holder whose mode scene code changes to one of its own processes before stage 7. Godot's `Node.can_process()` uses the node's own mode when it is not `INHERIT`, and no engine signal tells SceneCore that the mode changed. So the code cannot satisfy both "reads only at those times" and "does not receive the per-frame engine callbacks" for this case. Even the removed per-frame check missed a mode given after it ran in a frame (round 3 run path). The review itself says it "stays open until `scene-core.md` or `godot.md` sets that case". Writing `set_process(false)` or similar on every node would be a write that the mapping does not define, and it would not close the case either, because scene code can call `set_process(true)` and `Timer.start()` turns on internal processing. A spec proposal is in `## spec proposals`. After this fix, the case covers every mode given after a node was added. Before, it covered only a mode given within a frame after the check
