# review fix GameUpdateCore round 1

## done

- `GameUpdateCore` (Godot client core), commit `db89d38`
  - `_download_failure` (`client/godot/core/game_update_core/game_update_core.gd:629`) now checks the HTTP status before the `TOO_LARGE` status. A response with an HTTP status other than 0 or 200 is `[game_update_download_failed]` even when its body went over the max bytes. A 200 response over the max bytes is still `[game_update_invalid_file]`
  - Store redirect (`game_update_core.gd:431`): the core test replacement `_store_opener`, which skipped the whole platform branch, is replaced by two replacements that sit below the branch. `_url_opener` replaces `OS.shell_open` and returns an `Error`. `_page_script_runner` replaces `JavaScriptBridge.eval`. The browser runtime now runs the page script `window.location.assign(<store_url>)` inside `try`/`catch` through `_run_page_script` (`game_update_core.gd:447`, input boundary). When the script does not reply `ok` (e.g. `assign` threw), it leaves the error log `could not open the store URL`, the same as a native `shell_open` failure. `release` clears both replacements
  - Test support (`tests/support/game_update_test_case.gd`): in the browser runtime, the page script runner runs the real redirect script with real `JavaScriptBridge.eval`, inside a wrapper that passes a stub `window` as a parameter. The stub's `location.assign` records the URL instead of leaving the test page, or throws when the test sets `store_open_fails`. Natively, the URL opener records the URL and returns `ERR_CANT_OPEN` when `store_open_fails` is set. Because of this, every store redirect test now runs the platform branch of its runtime
- Last `ogw core test` runs: `godot GameUpdateCore BootstrapCore QACore UnitTestCore` passed, and the same modules with `--web` passed (`ogw core dependents GameUpdateCore`: client `BootstrapCore GameUpdateCore QACore UnitTestCore`, no server modules)
- `ogw code check core` result: type check, lint, dependency and secret all pass
- No engine-specific implementation rules document was written. `## <engine> build` of `tools/ogw.md` was not written

## unverified

- In the browser run, the redirect script is run against a stub `window` passed as a function parameter, not against the real `window.location`. The `Location` methods cannot be replaced, and calling the real one would move the test page away. The tests check that the script, as built by the module, calls `window.location.assign` with the unchanged URL and that its failure reply is logged. They do not check navigation of the real page
- The real `OS.shell_open` was not called in core tests. Opening a URL would start the host's browser. The only check is that its `Error` result is the value the branch reads
