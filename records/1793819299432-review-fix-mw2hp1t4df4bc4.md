- `ogw core test godot` and `ogw core test godot --web` of BadgeCore BootstrapCore ChatCore NoticeCore QACore UnitTestCore (BadgeCore and `ogw core dependents BadgeCore`): all pass. `ogw code check core`: all pass

## review

- R1-1: fixed. client/godot/core/badge_core/badge_core.gd:229-256: `load_saved` sets `_save_pending` only when an element was dropped (malformed, badge not in data, `persist` false), an element repeats a badge ID and item key already read, a memory count differs from the saved count, or memory has more persist items than the saved elements read. Values are compared, not element order or text. Tests: `test_load_saved_with_no_saved_key_and_no_persist_items_writes_nothing` (no `user` file is written after `load_saved` and `LocalDataCore.flush`), `test_load_saved_with_equal_values_in_another_order_writes_nothing` (the `user` file bytes on disk are unchanged, and a later `set_item` still saves), `test_duplicate_saved_element_is_saved_away`. Before the fix, the first two failed with the old `badge_core.gd` (checked by running test_save.gd with badge_core.gd of fd11015)
- R1-2: fixed. client/godot/core/badge_core/badge_core.gd:765: the 19-digit limit is `9223372036854775808` for a negative number and `9223372036854775807` otherwise. Tests: `test_long_limit_item_keys_are_saved_and_read_back` (item keys `-9223372036854775808` and `9223372036854775807` are saved, and after `release`, `init` and `load_saved` come back without a warn; it failed with the old code: 1 warn, count 0), `test_item_keys_out_of_the_long_range_are_dropped_with_a_warn` (`-9223372036854775809` and `9223372036854775808`)

## unverified

- The tests read the `user` file on disk through `CoreBuildInfo.storage_root + "local_data/"` with `FileAccess`/`DirAccess`, because `local_data` is a reserved folder of the `LocalDataCore` file API and `_` names of `LocalDataCore` are not allowed outside its folder
- `String.to_int` of `-9223372036854775808` returns the `long` minimum on this Godot build (the test passes); it was not checked on other engine versions
- A second `load_saved` call in one session (left open by the review) was not changed: on that call `_put_item` still sets `_save_pending` for the items it adds, since `_saving` is already true
