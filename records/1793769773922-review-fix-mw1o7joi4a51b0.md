## spec proposals

The three findings below have `spec change` `yes`, so the code was not changed for them. Each proposal is the fix the review file gives. Only the review ran R1-1 and read R1-3; this job did not reproduce them.

- R1-1 (`realtime-core.md:107`, `:394`): settle one behavior for a match found that a `close` of the same `poll` already left when the state returned to `Matching`. The review proposes that it is discarded and the member waits for the next room updated. Line 394 requires `Connecting`, while line 107 says the `close` has already left the match. That change also needs `_frame`, the test at `tests/test_room.gd:355`, and a new test on the P2P transport.
- R1-3 (`realtime-core.md:298`, `matchmaker.md:374`): the two specs together let a second `MATCH_FOUND` reach a member in a running match. The server removes that connection from the first session, while the client leaves the second match and stays `Playing` in the first. The review proposes either refusing `ROOM_START` and the host `MATCH_REQUEST` while a member is bound to a running match session, or having the client take the second match. This is also `D5` of `records/review-debt/RealtimeCore.json`.
- R1-4 (`realtime-core.md:299`): add "once per match" to the `warn` of a failed `connect_peer`. This keeps the code (`p2p_realtime_transport.gd:492`) and the test (`tests/test_p2p.gd:760`) as they are.

## review
