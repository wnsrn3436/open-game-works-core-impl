# update core: storage

## done

- module `storage` (server):
  - `set_seed_provider(fn)`: the provider is now `(request ID, user ID, request name) → random seed or none` (type `SeedProvider`, exported from `server/core/storage/index.ts`). It is called once per transaction that `run_request_transaction` opens, after the `user` row lock and the withdrawn check and before the ctx is made, so a `WITHDRAWN` transaction (and a `FAILED` transaction start) does not call it; `run_user_transaction` and `run_rollback_transaction` do not call it (`server/core/storage/tx.ts` `open_user`). `dev/index.ts` `StorageDev.set_seed_provider` takes the same type.
  - `make_seed(purpose name)` (new, module object only, not in `content`): `StorageMisuse` throw for a purpose name that is not `[a-z][a-z0-9_]*`; with a seed provider, the value it returns for (`''`, `0n`, purpose name), and secure random when it returns none or there is no provider (`tx.ts` `make_seed`).
  - `watch_db_wait(array)` (new): before server start only (throws once `begin_start` ran, i.e. after `start()` of the server instance); a value that is not an `Int32Array` with an element 0 is a `StorageMisuse` throw.
  - DB wait state and sync DB call metering: new `server/core/storage/db/meter.ts` (`DbMeter`). `Atomics.store` 1/0 around each synchronous DB call, and the count and real elapsed ms of those calls (the `server-time` system clock adapter, since the static check allows no other clock read).
    - PostgreSQL (`db/postgres.ts`): every blocking `Bridge.call_sync` except the connect of `open` and the worker `close`: `query` of the transaction and `read_db` connections (so every storage operation, `lock_game_row` and the lock step of `replace_game_rows`), `lock_key`, `begin_sync`/`commit_sync`/`rollback_sync` of the schema step. The async `begin`/`commit`/`rollback`/`autocommit` (per-user lock, free connection wait, `sweep_expired` deletes) are not metered.
    - SQLite (`db/sqlite.ts`): every node:sqlite call of the write and read connections (`query`, `run`, `exec`, so `BEGIN IMMEDIATE` tries, `COMMIT`, `ROLLBACK`), not the pauses between `BEGIN IMMEDIATE` tries.
  - DB failure counts: `counting_adapter` (`db/meter.ts`) wraps the adapter, so each statement, `lock_key` (`lock_game_row`), commit, transaction start and autocommit counts once by its final `DbError` kind (`lock`: SQLSTATE `55P03`/`40P01`/`40001`/`57014`, free connection wait, SQLite write lock waits; `connection`). The `read_db` rerun on a new connection and the transaction start that takes another connection happen inside the PostgreSQL worker, so they count only when the final result fails.
  - `read_db_metrics()` (new): `sync_calls`, `sync_wait_ms`, `lock_failures`, `connection_failures` from the instance's creation (the schema step included), then `wal_archive_failing` read through the `read_db` handle (counted in the next call). `false` on SQLite and when the statement fails (`index.ts` `read_db_metrics`, `wal_archive_failing`).
- tests: new `server/core/storage/tests/db-metrics.test.ts` (wait state in a query waiting on a `testing.hold_db` row, the same for `put_game_state` in a handler, staying 0 while a request's transaction start waits on the `user` row, sync counts and wait, `lock_failures` for a core `lock_game_row` `FAILED` and for the SQLite cross-instance write lock wait, `connection_failures` for a `pg_terminate_backend` mid-query and not for an idle-ended `read_db` connection that recovers, `wal_archive_failing` false on both DBs, `watch_db_wait` after start throws). `random.test.ts`: the `core/Resync` seed provider arguments, the once-per-request-transaction call (not for WITHDRAWN or the other transaction kinds), and the three `make_seed` items. `tests/helpers.ts` `InstanceOptions` gains `watch` and takes `SeedProvider`.
- runs: `ogw core test server storage` pass; the last `ogw core test server` (all server modules, which covers every server module `ogw core dependents storage` lists) pass on SQLite and PostgreSQL at HEAD; `ogw code check core` pass (type check, lint, dependency, secret).

Existing callers of `set_seed_provider` (`testing/dev/test_server.ts`, `logging/tests/helpers.ts`) pass a function of the request ID only, which still type-checks against the wider provider type, so I didn't change them. `matchmaker` (`make_seed` for the match `seed`; it still calls its own `new_seed()` in `matchmaker/realtime.ts:932`), `routing` (`watch_db_wait` with the front link array), `logging` (`read_db_metrics` metrics) and the `testing` check seed provider are those modules' own updates. ## spec proposals

- `wal_archive_failing`: the spec gives the statement `SELECT last_archived_time, last_failed_time FROM pg_stat_archiver`. The wire protocol of the adapter returns `timestamptz` as text in the session's DateStyle and TimeZone, which cannot be compared safely in TypeScript. So the implementation reads the same two columns as `CAST(EXTRACT(EPOCH FROM <column>) * 1000000 AS BIGINT)` and compares them as the spec says. Proposal: allow the columns to be read as epoch microseconds (or state the comparison only, not the literal statement).
- `### DB adapter` synchronous DB call: `stop` rolls back still-open transactions with a blocking rollback, and the spec says the rollback of a non-schema transaction is not a synchronous DB call. The implementation counts it, because the thread does block. Proposal: state that the rollbacks of `stop` are synchronous DB calls, or that the DB wait state and metrics after `stop` are unspecified.
- `watch_db_wait`: the spec gives no failure for an input that is not an `Int32Array`. The implementation throws `StorageMisuse`. Proposal: list it as a misuse.

## unverified

- `wal_archive_failing` `true` (a `pg_stat_archiver` with a failure after the last archive) is not tested: the throwaway PostgreSQL of `ogw core test` has archiving off, and `pg_stat_archiver` cannot be written. Only the comparison code covers that case.
