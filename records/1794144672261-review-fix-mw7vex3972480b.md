# review fix InputCore round 3

## done

- InputCore (Godot): `init` now fails with an error log when an element of `InputCore.padAxisSensitivities` is more than 10000 (new const `_MAX_SENSITIVITY`, `_read_sensitivities`), as `## errors` of the spec requires
- core settings schema: `"maximum": 10000` on the `items` of `InputCore.padAxisSensitivities` in `settings/core-settings.schema.json` and the generated `server/generated/core_settings_schema.json`
- Tests: `ogw core test godot` and `ogw core test godot --web` passed on InputCore and every module that `ogw core dependents InputCore` lists. `ogw code check core` passed (type check, lint, dependency, secret)
- No engine-specific implementation rules document was written, and `## <engine> build` of `tools/ogw.md` was not written

## spec proposals

none

## review

- R3-1: fixed. `client/godot/core/input_core/input_core.gd:2221-2223` rejects an element more than `_MAX_SENSITIVITY` (:54) with an error log, and the doc comment is updated (:2201-2203). Test: `test_init_fails_with_sensitivities_out_of_range` (`client/godot/core/input_core/tests/test_stick_axis.gd:113`) adds the cases [1000, 10001] and [1000, 3000000000] (the overflow case of the review); `init` fails with one error log for each. It also checks that [1, 1000, 10000] is accepted, that `list_pad_axis_sensitivities` fills [1, 1000, 10000], and that `set_pad_axis_sensitivity("right_x", 10000)` stores 10000 (:128-137)
- R3-2: fixed. `settings/core-settings.schema.json:1310` and `server/generated/core_settings_schema.json:1310` add `"maximum": 10000`. No test was added for this, because it is a schema value that the settings check reads, not behavior of the core code
- R1-2: fixed by the R3-1 and R3-2 fixes above. A value more than 10000 can no longer be stored in `_axis_sensitivity: PackedInt32Array`, so it cannot overflow

## unverified

- `server/generated/core_settings_schema.json` was edited by hand to match `settings/core-settings.schema.json` and was not made again with `ogw core spec`. The next `ogw core test` on main makes it again
- The server core tests were not run: no server module depends on InputCore, and the schema change only adds a bound that the current `core-settings.json` value [500, 750, 1000, 1500, 2000] meets
- Behavior with real gamepad hardware was not checked
