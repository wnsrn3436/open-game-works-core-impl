# review fix: RequirementCore round 3

## done

- `RequirementCore` (Godot client core), commit 7a3cbf5
  - Watch storage changed to buffers that grow only in `watch`, with `int` counts: `_free_slots` + `_free_count`, `_pending` + `_pending_count`, `_round` + `_round_count` (each as long as `_watches`), and an `int` link pool (`_link_next`, `_link_prev`, `_link_slot`, free chain `_free_link`) that holds rings of watch slots
  - Lists in the link pool: watches per requirement ID (`_id_heads`, replaces `_slots_by_id`), per UserState kind (`_state_heads`), per target name of `REQUEST_COMPLETED` / `UI_OPENED` / `UI_CLOSED` (`_request_heads`, `_opened_heads`, `_closed_heads`), per content event type (`_content_heads`), and time-dependent watches (`_time_head`). A head key stays until `release`, so frame code never adds or erases a `Dictionary` key
  - `register_judge` links each watch again with `_relink_watches` (UserState kinds of empty-target triggers, time dependence). This replaces `_count_time_watches`
  - `requirement_watch.gd`: `pending` / `batch_round` replaced by `queue` / `queue_index`; added `slot`, `id_link`, `trigger_links`, `state_links`, `time_link`

## review

- R3-1: fixed. `_remove_watch_at` (client/godot/core/requirement_core/requirement_core.gd:602) now only writes into fixed-size buffers, unlinks pool links (`_remove_link` :670, int writes only) and takes the watch out of its pending buffer by swapping the last entry in (`_dequeue` :780). No `append`, `remove_at`, `erase`, Dictionary key add or Packed array creation is left on the frame code path (`_on_frame` → `_remove_watch_at`, `_run_batch` :823 → `_remove_watch_at`). Buffers and pool grow only in `_store_watch` (:523), which `watch` calls. Added tests:
  - `test_the_frame_code_removes_watches_without_changing_a_collection_size` (tests/test_watch.gd:386): 10 owner watches and 2 watches whose callback becomes invalid are removed in frame code. The sizes of `_watches`, `_free_slots`, `_pending`, `_round`, `_owner_slots`, the link pool and every head dictionary do not change, the lists hold exactly the live slots, and 12 later watches reuse the slots and links without growing anything
  - `test_a_watch_removed_by_a_callback_before_its_turn_in_the_round_is_not_judged` (tests/test_watch.gd:512): a callback unwatches a watch that is still waiting in the running round. That watch is taken out of the round buffer and is not called back
  - `_assert_initial_state` (tests/test_lifecycle.gd:35) checks that `release` empties the new buffers, the pool and the heads
- R3-2: fixed. `_run_batch` (:823) swaps the pending buffer with the round buffer and goes over only the `_round_count` watches of the round. Marks made during the round go to the next round, and the round limit drops only the `_pending_count` entries. `_on_user_state_changed` (:866), `_on_named_trigger` (:872), `_on_content_event` (:878) and `_mark_time_watches` (:884) look up one head and walk only that list (`_mark_list` :682). No path goes over all `_watches` slots or over each watch's trigger list any more. Full scans remain only in `register_judge` (`_relink_watches` :590), which is not frame code. Added tests:
  - `test_a_trigger_marks_and_a_round_judges_only_the_watches_of_that_trigger` (tests/test_watch.gd:436): with 30 content watches, one `UI_OPENED` watch and one `TutorialProgressUserState` watch, each list holds exactly its watches. A `UIOpenedEvent` makes one pending evaluation, and the next frame calls the time-dependent judge hook once, not 31 times. An `ItemBalanceUserState` change marks nothing. A time recheck marks exactly the 31 time-dependent watches. `unwatch` takes the watch out of its lists
  - `test_register_judge_puts_a_watch_with_an_empty_user_state_target_into_the_lists_of_the_new_kinds` (tests/test_watch.gd:490): an empty-target watch made before the hooks exist joins the kind lists at `register_judge`, and a later `register_judge` links each kind only once
