# update core: storage — fail_transaction

## done

- `storage` (server): new operation `fail_transaction(ctx or game tx)`, exported on the storage module object for core modules (not on `storage.content`).
  - `server/core/storage/core.ts`: `TxState.failed`; `user_state_of` and `any_state_of` throw a `DbError` (`lock`, code `failed`, not a `StorageMisuse`) for a transaction that `fail_transaction` marked, so every later storage operation on it throws. An ended or unknown ctx/tx is still a `StorageMisuse`.
  - `server/core/storage/tx.ts`: `fail_transaction` marks `failed` and `broken`, so `query` through any `db` handle of it (also one taken before) and `q` throw, `run_savepoint` throws after its function and its commit does not run; `body` returns `FAILED` for a marked transaction when the function throws, before the statement failure rule (also when the function throws the value of its own failed statement), and when it returns (also `GameError`, `pass` of `run_user_transaction`, and any result of `run_rollback_transaction`). `after_commit` / `on_commit` functions of the transaction are not called.
  - `server/core/storage/index.ts`: `fail_transaction` in the `Storage` interface and the module object.
  - Core tests: `server/core/storage/tests/fail-transaction.test.ts`, including the spec `## test` item (put_state, fail_transaction, get_state throws, caught, normal return → `FAILED`, put_state not saved), on SQLite and PostgreSQL.
- Changes outside the module: none.
- Last runs: `ogw core test server` with storage and every module of `ogw core dependents storage` (all 40 other server modules) on HEAD: all pass. `ogw code check core`: type check, lint, dependency, secret all pass.
- No engine-specific implementation rules document; `## <engine> build` of `tools/ogw.md` not written.

## spec proposals

- `fail_transaction` called a second time on a transaction it already marked throws (read as "every later storage operation on it throws"). If a module (e.g. `item-ledger` for nested hook failures) needs to call it more than once, the spec could say the call on a marked transaction does nothing.
- On a marked transaction, a core-module `lock_game_row` and `replace_game_rows` throw, while after a failed statement they are `FAILED`. The spec text for `fail_transaction` says every later storage operation throws, so I followed that; the spec could say this explicitly since it differs from the statement failure rule it refers to.
- The spec does not say whether the value thrown by later operations is a `StorageMisuse`. I made it not one (a `DbError` of kind `lock`), as after a failed statement. The spec could say this.
