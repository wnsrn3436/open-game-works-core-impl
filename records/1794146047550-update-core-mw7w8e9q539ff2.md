# update core: LocalizationCore (weight 0 keeps the font's own wght)

## done

- Module: LocalizationCore (Godot), commit fae5e67c.
- Reproduced first. A new test used a font key whose font is a `FontVariation` setting `wght` 700 over the test `wght` axis font, with `bodyFontWeight` 0. Before the fix the default font drew `A` at 60.0 (weight 400) instead of 84.0 (weight 700), and the chain had no `wght`. A headless Godot 4.7.2 probe confirmed the cause: a `FontVariation` whose `base_font` is another `FontVariation` drops all of the inner variation, so `wght` 700 drew at 60.0, and the glyph spacing of `BB` measured 120 instead of 127.
- Fix (`client/godot/core/localization_core/localization_core.gd`):
  - `_variation_of(font)`: the chain, and each weighted fallback, is now a `FontVariation` of its font that copies that font's own variation settings when the font is a `FontVariation`: `variation_opentype`, face index, embolden, transform, OpenType features, the four spacings and baseline offset. A first font with weight 0, or with no `wght` axis, now draws as it draws by itself.
  - `_set_weight` replaces only the `wght` coordinate. A key given as an axis name is matched through `name_to_tag`. The font's other coordinates are kept.
  - Unweighted fallbacks are still added as the font itself (the engine already draws a fallback with its own variation). Fonts that are not a `FontVariation` get the same chain as before.
- Tests (`tests/test_font_weight.gd`, new resources `font_weight_axis_700.tres`, `font_no_weight_axis_spaced.tres`):
  - the new spec `## test` item: `bodyFontWeight` 0 with a first font that sets its own `wght` 700 draws at 700 (width 84) with no warn log;
  - `headingFontWeight` 800 on that font draws at 800;
  - a first font without the axis that sets its own glyph spacing keeps it in both text styles. A fallback that sets its own `wght` 700 draws at 700 in body (weight 0) and at 800 in heading.
- Last runs on fae5e67c: `ogw core test godot` and `ogw core test godot --web` with LocalizationCore and all 26 modules of `ogw core dependents LocalizationCore`: all pass. `ogw code check core`: type check, lint, dependency and secret all pass.
- No engine-specific implementation rules document, and no `## <engine> build` of `tools/ogw.md`, was written.

## spec proposals

- The spec defines the default weight as "the weight the font of the font key is drawn with by itself". The implementation applies the same principle to the other variation settings of a `FontVariation` font key: spacing, embolden, transform, features, other axes. This holds both when weight is 0 and when only `wght` is replaced. The spec could say that the font chain draws each font as it draws by itself, except for `wght`.
