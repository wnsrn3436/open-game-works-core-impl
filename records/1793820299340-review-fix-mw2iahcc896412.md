## spec proposals

- `### banner` of ad-core does not say what happens when a superseded `open_banner` succeeds after the banner of a later `show_banner` is already open. The adapter `close_banner` takes no unit, so AdCore cannot close only the late banner. The implementation closes and then opens the later banner again (one extra `open_banner`). Proposal: write this in `### banner`, or give `close_banner` / `open_banner` a banner handle so that one banner can be closed alone
- `## DEV` of ad-core does not say whether the fake values last past `release`, or what the `fake_*` operations do when AdCore holds a non-fake ads adapter. The implementation clears them at `release` and does nothing (no log) on another adapter, the same as `PushCoreDev`. Proposal: state both in the spec
