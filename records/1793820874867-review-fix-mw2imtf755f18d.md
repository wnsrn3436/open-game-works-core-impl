## review

- R1-1 fixed: added test client/godot/core/notice_core/tests/test_maintenance.gd:24 `test_back_input_does_not_close_the_maintenance_popup`. It opens the maintenance popup through `wait_maintenance_clear`, then sends one escape key back input through `InputCoreDev.inject_device_input` (helper `press_back`, test_maintenance.gd:44), which is the path `UICore` reads. It asserts that the popup count stays 1, that `waiting.done` stays `false` and that no second `GetNotices` is sent. Then `[notice_retry]` ends the wait. Checked by mutation: with `param.back_button = 0` at client/godot/core/notice_core/notice_core.gd:601, this test fails (popup count 0, request count 2). The other tests do not fail
- R1-2 fixed: added test client/godot/core/notice_core/tests/test_image.gd:112 `test_cancel_ends_a_download_of_the_default_downloader`. It starts `download` of the default downloader (`NoticeCore._downloader`) against a loopback HTTP server response and calls `cancel()` in the same frame, before the response can arrive. It asserts that `download` returns `CANCELLED` with an empty body, that the core node has no `HTTPRequest` child left and that a second `download` afterwards returns `DONE` with the PNG body. Mutation checks:
  - Replacing `_finish_http(result)` in `http_cancel` (client/godot/core/notice_core/notice_core_node.gd:57) fails the native run: the download does not end, the request is not freed and the second download fails
  - Replacing `_finish(result)` in `cancel` (client/godot/core/notice_core/web_image_downloader.gd:67) fails the `--web` browser run: the download does not end and the second download fails
