# update core: UICore focus mode start input

## done

- `UICore` (Godot), `client/godot/core/ui_core/ui_core.gd`
  - The key direction input that starts focus mode no longer calls `grab_focus()` and `set_input_as_handled()` in `_on_input`. It sets `_focus_start_pending` and calls `_start_focus` with `call_deferred`, so focus is put after the engine has handled that input. The input moves no focus, is not marked handled and goes on to the UI stage and the world stage of `InputCore`. This is the same path for every start device (`KeyboardMouse`, and `Touch` where the device detection of that same input makes it `KeyboardMouse`).
  - While `_focus_start_pending` is set, `_update_focus` does not grab focus. Without this, a `Touch` → key start grabbed focus inside `InputCore._input` (the `InputDeviceChangedEvent` handler) before the GUI, and the engine then moved focus and marked the input handled.
  - A direction input that scrolls the body of the top system popup is kept in `_scroll_event`, and `_on_unhandled_input` consumes it when no UI element took it. It is consumed after the `_input` of `InputCore`, so device detection still sees it. While focus mode is on, the focused system popup button still takes up/down with `accept_event()` as before.
  - `_update_focus_callable` was replaced by `_start_focus_callable`; `_reset_statics` clears it, `_focus_start_pending` and `_scroll_event`.
- `client/godot/core/ui_core/system_popup_view.gd`: `scroll_by` returns whether there is a body to scroll.
- Tests
  - `tests/test_focus.gd` `test_key_direction_starts_the_focus_mode`: `KeyboardMouse`, focus mode off, popup with initial focus `Second`; one Up press presses `cutscene_advance` bound to Up, and in that frame `Second` has focus (not moved to `First`); the release moves no focus; the next Up moves focus to `First`; Enter clicks; a mouse move removes focus.
  - `tests/test_focus.gd` `test_key_direction_from_touch_starts_the_focus_mode`: the same start from `Touch`. The device becomes `KeyboardMouse`, the action is pressed and focus does not move.
  - `tests/test_system_popup.gd` `test_key_direction_that_starts_the_focus_mode_scrolls_the_body` (from `KeyboardMouse`) and `test_key_direction_from_touch_that_starts_the_focus_mode_scrolls_the_body` (from `Touch`): a Down press that starts focus mode scrolls the body by the step, does not press `cutscene_advance` bound to Down, and the system popup button gets focus; the next Down scrolls again and focus stays.
  - `tests/test_lifecycle.gd`: release clears the new statics.
- Checked that the new tests fail without the change: the focus test fails on the old code (the action is not pressed); the scroll tests fail when the `_scroll_event` consumption is removed; the Touch focus test fails when the `_focus_start_pending` guard in `_update_focus` is removed (focus moves to `First`).
- Last runs: `ogw core test godot` and `ogw core test godot --web` with UICore and every module that `ogw core dependents UICore` lists: all pass (Godot: 4 render passes skipped, see `## unverified`). `ogw code check core`: pass.
- No engine-specific implementation rules document or `## <engine> build` of `tools/ogw.md` was written.
