## unverified

- The R1-1 tests show the locks only on the PostgreSQL run. On SQLite the whole database is serialized by the write transaction, so removing the locks makes no SQLite test fail
- The R1-1 tests rely on this server's operation reaching the lock within the holder's 200 ms commit delay. When it is slower, the holder commits first and the test passes without showing the wait. It does not fail falsely
- R1-6 and R1-7 were checked by counting statements. Time was not measured
- The R1-6 and R1-7 statement-count tests were not run against the code from before the fix. That code has no `delete_files` and runs one statement per value, so it gives 1001 statements where the test expects 3
