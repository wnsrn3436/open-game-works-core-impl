# SceneCore review fix round 2

## done

- `SceneCore` (Godot), commit `3c0e50f` on `agent/mw2lxrgq9a149f`
  - New `client/godot/core/scene_core/stop_check_node.gd`: the stop check node `SceneCoreStopCheck`, a child of the tree root made in `init` and freed in `release`, with `process_priority` and `process_physics_priority` at the lowest int (`_STOP_CHECK_PRIORITY`), `PROCESS_MODE_ALWAYS`. It runs `_check_stopped` in `_process` and `_physics_process`, so the check runs before every other node's callback in both the frame and the physics frame. The core node no longer runs the stop check; it keeps `_check_frame` at its old priority, so the deadline still reads the `TimeCore` time of the current frame
  - The stop check reads `_watched`, a `Dictionary[Node, bool]` of the nodes under the scene holder, instead of walking the tree recursively (`_stop_tree` removed). `_hide_tree` fills the set at stage 4, `node_added` adds to it and a new `SceneTree.node_removed` connection removes from it, so a node that leaves the holder or is freed leaves the set
  - The stop check runs only while `_watching` is true (`_set_watching` turns the stop check node's `set_process`/`set_physics_process` on and off). It starts after the `_hide_tree` of stage 4 and ends at stage 7, in `_fail` and in `_end_with_restart`, so it no longer runs every frame after a fatal failure or a restart until `release`
  - Nodes are disabled after the loop over the set, because disabling a node sends notifications that scene code may handle by adding or removing nodes

- Tests: `ogw core test godot SceneCore BootstrapCore QACore ShortcutCore TutorialCore UnitTestCore` passed natively (QACore skipped there: the render pass did not run because the macOS screen was locked) and with `--web` (all six passed). `ogw code check core`: type check, lint, dependency and secret all pass

## spec proposals

- R2-1 (spec change yes, not fixed): `open-game-works-core/skills/client-core/engines/godot.md:291` says both that SceneCore writes no property of a node under the holder and that `_process()`/`_physics_process()` do not run under the holder. A `PROCESS_MODE_ALWAYS` node breaks the second unless its `process_mode` is written. Godot has no other way to stop such a node while it stays in the tree. `SceneTree.paused` does not stop it, and removing it from the tree runs `_exit_tree`. A `set_process(false)` write would have the same problem of not being able to tell a scene-code write apart. Proposal: allow SceneCore to write `process_mode` under the holder. Then set in `scene-core.md` `### scene` that a run-mode change scene code makes from stage 4 until before stage 7 is kept at stage 7, as for visibility. The code would then need a way to tell its own `PROCESS_MODE_DISABLED` from one scene code writes: for example, write the restore only when the node's mode is still the one SceneCore wrote and no scene write was seen. Since Godot has no change signal for `process_mode`, the rule may have to say that a scene code write of `PROCESS_MODE_DISABLED` to a node SceneCore stopped is kept, while other writes are replaced at the next stop check
- Mid-frame mode change: the stop check node runs first in each frame and physics frame. Scene code that resumes inside another node's callback in the same frame can still give a node that runs later in that frame a mode of its own before the next check: for example, `on_prepare` awaiting a server response that a core node delivers from its `_process`. That node gets one callback before the next check. Without writing node properties outside the stop check, nothing can prevent this; the R2-1 mechanism has to settle it. Proposal: state in `godot.md` either that the gap is accepted (at most one callback in that frame) or another mechanism
- R2-2 (fixed in code as far as the spec allows): the check is still linear in the node count under the holder. A check that does not read every node each frame needs the spec to set what happens to a mode that scene code gives a node after `on_preload` returns (the reviewer's suggestion). Proposal: decide this together with R2-1. For example, stop only the nodes from the stage 4 walk, the walk after `on_preload` and `node_added`, and keep whatever mode scene code gives afterwards
- R1-2 (spec change yes in the input, not fixed): the review file says the spec now settles it, because `godot.md:291` gives the `RenderingServer` mechanism. The input line marks it `spec change: yes`, which takes precedence, so `visible` is still written at `scene_core.gd` `_hide_if_top`/`_show_hidden` and the `scene-core.md` test item "an object directly under the scene root that `on_prepare` hides is still hidden" has no test. If it is reopened with `spec change: no`, the fix is to implement the `RenderingServer` hiding of `godot.md:291` and add that test

## review

- R2-2: fixed. `client/godot/core/scene_core/scene_core.gd` `_check_stopped` (reads the `_watched` set kept by `_hide_tree`, `_on_node_added` and `_on_node_removed`, with no tree walk). `_set_watching(false)` at stage 7, in `_fail` and in `_end_with_restart` stops the stop check node from processing.   - `test_stop_check_runs_only_from_stage_4_until_stage_7_on_the_nodes_under_the_holder`: the stop check processes only during the hiding; the set equals the nodes under the holder; added nodes join; removed and freed nodes leave; a node taken out of the holder is not stopped any more
