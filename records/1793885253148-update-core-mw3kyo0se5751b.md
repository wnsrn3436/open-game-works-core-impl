# update core: InputCore

## done

- Module `InputCore` (Godot) and the `InputCore` check of the data tool, matched to the spec diff `2e8185b..HEAD` of `input-core.md` (the `godot.md` diff has no change that reaches InputCore)
- mouse input made from touch comes to step 1 right before its touch input: Godot already dispatches the emulated mouse event (`DEVICE_ID_EMULATION`) from `Input.parse_input_event` before the touch event it is made from, so the handling did not change. `_on_emulated_mouse` now states this in its doc comment (`client/godot/core/input_core/input_core.gd`). `test_mouse_input_the_engine_made_from_touch` (`tests/test_gesture.gd`) now checks that a UI element gets mouse button, touch, mouse motion, drag, mouse button, touch in that order (`InputCoreTestControl.gui_input_classes`)
- `get_keys` fills at most the larger of `InputCore.maxKeysPerAction` and the default binding length; `init` succeeds on a default binding longer than the limit: the code already did this (the binding stride is the larger of the setting and the longest default binding, and the general overflow rule logs only when the buffer is smaller than the binding). New core test `test_a_default_binding_longer_than_the_limit` (`tests/test_key_binding.gd`): `init` succeeds, `get_keys` and `get_pad_buttons` with a buffer of the binding length fill the whole binding without a log, the last key presses the action, and `set_keys` and `set_pad_buttons` with the same list are `false` without a log
- `maxKeysPerAction` and `maxPadButtonsPerAction` meaning changes: no code change; they are already only the limits of `set_keys` and `set_pad_buttons` (and the count check of `load_keys`)
- `input_prompt` data check: added the new rule "a `name` text of any language with an input prompt token is `translation_format`" to `tools/data-tool/src/checks/InputCore.ts`. It reports the source cell and each translation of a language other than the source language (the source language file holds the source text again, so it would report the same text twice). Tests in `tools/data-tool/tests/input-core-check.test.ts`: tokens in the source text and in a `ko` translation, `{count}` and `{action}` that are not input prompt tokens pass, and no report when `InputCore` is not in `--modules`
