# AuthCore review fix (round 2)

## done

- AuthCore (Godot), commit 5acc0e5f
  - `_storage_call` is split into `_storage_begin` (puts the operation in the queue and returns its wait) and `_storage_end` (waits and gives the outcome; `null` for an ended wait, as before). `_storage_call` behaves as before (client/godot/core/auth_core/auth_core.gd:1003-1037)
  - `_block_age` (auth_core.gd:1416) now starts the storage remove first. Before it waits, it deletes the session in memory and the pending token, writes the age block marker, and calls `_end_session(AGE_BLOCKED)`, which sets the provider to none, calls `NetworkCore.set_session_provider(null)` and `LogCore.set_analytics_allowed(false)`, and publishes `SessionEndedEvent(AgeBlocked)`. Then it waits for the remove. It returns `false` when `release` or `clear_dev_values` ended that wait
  - `prepare_consent` returns `Failed` when `_block_age` reports an ended wait (auth_core.gd:1207)
- No engine-specific implementation rules document written; `## <engine> build` of `tools/ogw.md` not written
- Tests: `ogw core test godot` and `ogw core test godot --web` with AuthCore and its dependents (AdCore, BootstrapCore, PaymentCore, PushCore, QACore, RealtimeCore, RemoteConfigCore, TutorialCore, UnitTestCore): all pass. `ogw code check core`: type check, lint, dependency and secret pass

## review

- R2-1: fixed. client/godot/core/auth_core/auth_core.gd:1416 (`_block_age` ends the session in memory before the storage-remove wait and returns `false` when the wait was ended), auth_core.gd:1207 (`prepare_consent` returns `Failed` then), auth_core.gd:1011-1037 (`_storage_begin` / `_storage_end`). Added test: client/godot/core/auth_core/tests/test_consent.gd:129 `test_clear_dev_values_during_the_age_block_remove_ends_the_session_and_fails_boot_login`. It holds the remove and calls `AuthCoreDev.clear_dev_values()`, then asserts that `boot_login` is `Failed`, there is no session or pending token, `AuthCore._provider` is null, a `NetworkCore.send` fails without a request and without an AuthCore error log (the session provider is none), analytics is not allowed, the `auth/age_blocked` marker exists, `SessionEndedEvent(AgeBlocked)` was published once, the storage item is gone after the held remove ends, and there is no AuthCore error or warn log. Running this test file with the auth_core.gd of HEAD before the fix fails it: the status (`AgeBlocked` instead of `Failed`), the provider is not null, no `SessionEndedEvent`, 2 AuthCore error logs, and the `NetworkCore.send` hangs until the test time limit
  - Order change: in-memory session end and marker write now happen before the remove ends, not after. Spec `### age and privacy choices` step 2 sets what happens, and nothing observes the order of the storage remove against the event except storage itself. The remove is put in the queue before the event is published, so a login that a `SessionEndedEvent` subscriber starts writes its item after the remove. On `release` during the remove wait, the marker and the session end are now done before the release (before, the marker was not written); `prepare_consent` returns `Failed` in that case too (before, `AgeBlocked`), which matches the lifecycle rule that a stopped operation returns its failure value
