# review fix GameUpdateCore round 1

## done

- `GameUpdateCore` (Godot client): `deploy_list.gd` `is_version` no longer has the 18-digit limit on each part (`_VERSION_PART_MAX_DIGITS` removed). It now accepts exactly what server `game-update` publish `VERSION` accepts: three decimal integers without leading zeros, of any length. `compare_versions` compares each part as a decimal string (leading zeros removed, the longer string is greater, equal lengths compare lexically) instead of `to_int`, so parts beyond the 64-bit range compare exactly and raise no engine overflow errors
- Core tests added in `client/godot/core/game_update_core/tests/test_app_version.gd`
- No engine-specific implementation rules document was written. `## <engine> build` of `tools/ogw.md` was not written
- `ogw core test godot GameUpdateCore BootstrapCore QACore UnitTestCore` and the same with `--web` pass on commit d2de9bf6. `ogw code check core` passes
