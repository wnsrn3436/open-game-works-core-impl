# update core: InputCore stick axis options

## done

- Module `InputCore` (Godot, `client/godot/core/input_core/input_core.gd`), commit `180de8a2`:
  - New operations `set_pad_axis_inverted`, `is_pad_axis_inverted`, `set_pad_axis_sensitivity`, `get_pad_axis_sensitivity`, `list_pad_axis_sensitivities` (`PackedInt32Array` caller buffer, ascending order, overflow error log), `reset_pad_axes`. The stick axis name argument is `String`, and permille is `int`
  - Source strength of a gamepad axis direction of a `Gameplay` action on a stick axis: an inverted axis takes the other direction's strength, then strength × S ÷ 1000, capped at 1. Other sources keep the direction strength. The block stage (`_axis_hits`), device detection (`_axis_presses_action`), press (`_press_axis`) and release (`_release_axis`) all judge with this source strength. Key wait still uses the direction strength. `back` (a `Ui` action) is unchanged
  - Prompt input of a gamepad family follows inversion for `Gameplay` actions (`_first_pad_name`)
  - Changing an option (set_*, reset_pad_axes, and an option that load_keys changes) first releases the pressed `Gameplay` sources of that stick axis on every gamepad slot. These releases are not device inputs, so their released frame is the current frame
  - Saves to `device`: `InputCore.pad_axis_inverted` (names in stick axis order) and `InputCore.pad_axis_sensitivity` (`<name>=<permille>`). A key whose list becomes empty is deleted. `reset_pad_axes` deletes both keys and publishes `InputPromptChangedEvent` once when it turns at least one inversion off
  - `load_keys` applies saved options. It leaves one warn and skips each of these: a name that is not a stick axis name, a malformed sensitivity element, a value not in `InputCore.padAxisSensitivities`, and a stick axis with two or more elements in one key (one warn per axis). It publishes one `InputPromptChangedEvent` per call when it applied a binding or a saved inversion
  - `init` reads and checks `InputCore.padAxisSensitivities`: 1 to 10 elements, contains 1000, every element ≥ 1, no repeats. Otherwise it leaves an error log and fails. `release` resets the options to default and keeps the saved keys
- Tests: new `tests/test_stick_axis.gd` (11 tests) covers every new stick axis `## test` item: inversion with release/init/load_keys, prompt and event, sensitivity and key wait, the list with 3/10/11 values, wrong names and values, release on change, `reset_pad_axes` vs `reset_pad_buttons`/`reset_keys`, device detection and the block stage, and `load_keys` warns. `test_lifecycle.gd` adds the stick axis options to the release item. `InputCoreTestCase` sets `InputCore.padAxisSensitivities` to [2000, 1000, 500]
- No other module's code changed. No engine-specific rules document or `## godot build` section was written

## spec proposals

- `load_keys` releasing sources: the spec lists only `set_pad_axis_inverted`, `set_pad_axis_sensitivity` and `reset_pad_axes` as releasing affected pressed sources first. The implementation also releases them when `load_keys` changes an option, so no source keeps a strength computed with the old option. Proposal: add `load_keys` to that sentence, or state that it does not release
- Duplicate counting in `load_keys`: the spec does not say whether a sensitivity element with a valid name but a wrong value counts toward "two or more elements in one key". The implementation counts every element with a well-formed `<stick axis name>=<integer>`, before it checks the value, the same way `load_keys` counts saved binding items per action. Proposal: state this in the spec
