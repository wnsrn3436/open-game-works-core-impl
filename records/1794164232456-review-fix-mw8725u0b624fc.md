A `Withdraw` request whose handler deletes the user and answers `INVALID_REQUEST` commits with `user_deleted` `true`. The test checks that `idempotency_withdrawn_response` has no row for that token hash and request ID, and that `find_withdrawn_response` returns none. Mutation check: with line 202 changed to `if (!ctx.user_deleted) return;`, the test failed on SQLite and PostgreSQL (the row check found a row). With the line restored, it passes.
  - The fix said a resend should call the handler again. That cannot happen here: the user deletion is committed, so the resend's user transaction answers `WITHDRAWN` before the handler runs. So the test checks the part of the spec's "handled again from the start" that can be observed: the resend gets no replayed error response, reaches the user transaction (`send` rejects with `WITHDRAWN`), and the handler call count stays 1.
