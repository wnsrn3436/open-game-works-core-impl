## spec proposals

- `storage`: add an operation that reads several items of one list kind by a list of item IDs in one query, with the same read conversion as `get_state`, e.g. `get_states(ctx, list kind, list of item IDs)` → list of values in ascending order of item ID. Reason: the R2-1 fix had to undo the R1-2 fix. `add_progress` again runs one `SELECT` per in-window mission of the counter, because `list_state` (the only multi-item read) also reads, and so converts, the rows of other counters, and a `FAILED` conversion of one of them throws. With that operation, `add_progress` could read only its counter's rows in one query. Until the spec has it, R1-2 / D2 (efficiency) cannot be fixed without breaking R2-1 (correctness)
