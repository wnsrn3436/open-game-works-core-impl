# review fix storage round 1

## done

- `storage`: the server start fill of null `public_code` (`fill_public_codes`) now runs each fill UPDATE on PostgreSQL inside the savepoint `fill_public_code` (`fill_update`, server/core/storage/schema.ts:324). On a unique violation (SQLSTATE `23505`) it rolls back to the savepoint and picks again, so a code that another server instance's `create_user` inserted and commits while the fill waits no longer aborts the schema transaction. Any other error is rethrown and still fails server start. SQLite keeps the single UPDATE, because `BEGIN IMMEDIATE` makes every code the `NOT EXISTS` sees committed
