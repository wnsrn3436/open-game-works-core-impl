## review

- R1-1 fixed: added `test_skipping_to_the_end_before_a_later_step_starts_changes_the_offset_of_an_arranged_element` (`client/godot/core/tween_core/tests/test_arranged.gd`). On an arranged element, step 1 `Opacity`, step 2 `Position` (10, 0); `skip_to_end` at 50 ms (during step 1); asserts `offset_transform_position` is (10, 0), `position` is the place the parent gives, and both stay after `queue_sort`, with the drawn origin 10 to the right. Checks the behavior at `client/godot/core/tween_core/tween_core.gd:725`. With the mutation of the finding (`var arranged: bool = change.arranged`) applied, this test fails (offset (0, 0), position (10, 0) instead of (54, 0)); it passes on the unchanged code
- R1-2 fixed: added `test_rotation_and_scale_from_their_current_values_start_from_the_offset_of_an_arranged_element` (same file). Sets `offset_transform_rotation` to 40° and `offset_transform_scale` to (2, 3) on an arranged element, plays `Rotation` to 0 and `Scale` to (1, 1) without start values, and asserts the midway values are 20° and (1.5, 2), with `rotation` and `scale` unchanged. Checks the reads at `client/godot/core/tween_core/tween_core.gd:1035` and `:1036`. With the rotation read changed to `control.rotation`, it fails (0 instead of 20); with the scale read changed to `control.scale`, it fails (1 instead of 1.5 and 2). Each mutation was run separately with `ogw core test godot TweenCore --file`; it passes on the unchanged code
