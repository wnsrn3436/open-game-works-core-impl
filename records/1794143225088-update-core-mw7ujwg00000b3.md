## done

- Module: `BootstrapCore` (Godot), commit `3468e346` on `agent/mw7ujwg00000b3`. No other module's code changed. `TimeCoreDev.set_random_base` and `TimeCoreDev.set_frame_step` were already on main (the TimeCore job), so no caller had to follow a rename
- Launch values are JSON strings: `_merge_launch_values` (`client/godot/core/bootstrap_core/dev/bootstrap_core_dev.gd`) keeps the error of the first value that is not a JSON string, in the page/command line file or in the file the export holds, in `BootstrapCore._launch_value_error`. `make_dev_build_info` makes `InitModules` 1 fatal with that error before any other launch value check
- `OGW_RANDOM_BASE`: checked against `-?[0-9]{1,19}` inside int64 (`_is_int64_text`: digit check, then a same-length digit string compare against `9223372036854775807` / `9223372036854775808`; `_int64_of` builds a negative value downward so int64 min does not overflow). `OGW_FRAME_STEP_FPS`: checked against `[1-9][0-9]{0,3}` (`_is_fps_text`). Either one outside its syntax is fatal in `InitModules` 1. The parsed values are stored with the build info (`BootstrapCore._has_random_base`, `_random_base`, `_frame_step_fps`), so a restart and an update reboot, which do not read build info again, still have them. `shutdown` clears them
- New DEV hook `pass_time_launch_values` (`bootstrap_dev_hooks.gd`, implemented in `bootstrap_core_dev.gd`). `_pass_adapters` calls it in `InitModules` 2 of every boot, before `apply_test_replacements` and before module `init`. In a dev run it calls `TimeCoreDev.set_random_base` / `TimeCoreDev.set_frame_step` when the value is not empty. A build without DEV code has no DEV entry, so STG/PROD have neither call
- `client/godot/core/web/ogw-shell.html`: when the page URL has `ogw_launch_values`, the shell resolves it against the page. It rejects a value that is not a `/`-path on the page's origin, fetches it with `cache: no-store`, puts it into the engine file system at `/tmp/ogw_launch_values.json` with `engine.preloadFile` (copied in before `callMain`), and starts the game with `--launch-values=/tmp/ogw_launch_values.json` added to `GODOT_CONFIG.args` as a user argument. It adds `--` first when the args have no `--`/`++`. Without the parameter the args stay as they are. A rejected value or a failed fetch shows the shell's failure notice and the engine does not start
- `res://generated/launch_values.json` is still read after the command line file, for the names that file did not give. That is the fallback: "a value the page does not pass takes the export's". I did not add a gate on "is an export", because `OS.has_feature()` is banned in core (godot.md `## static check`, and `ogw core test` refused my first version). No other API tells an export from a project run. The native-run case still holds: the harness tool writes that file only into the copy it exports for `device performance`, and the DEV preset's `exclude_filter` drops it otherwise (ogw.md, `generated/launch_values.json is written only for the check export...`). So a dev run of the project as it is never finds the file. The current code therefore did not read it in a native run. See `## spec proposals` 3
- Core test state added: `BootstrapCore._test_launch_values_path` (read in place of the command line file) and `_test_export_launch_values_path` (read in place of `res://generated/launch_values.json`). Both are cleared by `shutdown`

## spec proposals

1. `BootstrapCore` `## DEV` / godot.md `## module`: a launch value file that is not a JSON object (or not JSON) is not covered by the spec. The current code, unchanged, leaves an error log and goes on without that file's values. To match "a passed value that is not text is fatal", make a launch value file that is not a JSON object fatal in `InitModules` 1 as a launch value check failure
2. godot.md `## module` (browser runtime launch value file): say what happens when the `ogw_launch_values` value is not a same-origin URL path or the file cannot be fetched. The shell now shows its failure notice and does not start the engine, so the test host sees no `PUT /started`. Also name the engine file system path (now `/tmp/ogw_launch_values.json`), or say it is the shell's choice
3. godot.md `## module`, "When a DEV export has `res://generated/launch_values.json`": core cannot tell an export from a project run without `OS.has_feature()`, which is banned. State that only the harness tool's export copy holds that file, so reading it whenever it exists is the rule. Otherwise name an allowed way to tell an export (e.g. allow `OS.has_feature("template")` for `BootstrapCore`)
