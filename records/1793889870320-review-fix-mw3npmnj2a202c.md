## review

- R4-1: fixed. Added tests in `client/godot/core/message_core/tests/test_prepare.gd`:
  - `test_release_while_prepare_waits_for_the_toast_prefab_stops_prepare` (line 161), `test_release_while_prepare_waits_for_the_black_box_prefab_stops_prepare` (line 166) and `test_release_while_prepare_waits_for_a_tween_preset_stops_prepare` (line 171), through the helper `_check_release_during_prepare` (line 246). Each one starts `prepare`, which waits for the resource load of that case. It calls `MessageCore.release` while the resource is not yet in the global scope, then waits until `prepare` returns. The helper then asserts five things:
    - the load ended (the key is in the global scope)
    - `prepare` returned `false`
    - no `MessageCore` error log
    - `MessageCore.is_initialized()` is `false`, `_prepare_state` is `_PREPARE_NONE`, and `_toast` and `_black_box_object` are `null`
    - `init` and `prepare` succeed again, with no log, and a toast shows its text
  - `test_prepare_stopped_by_release_leaves_the_next_init_unprepared` (line 176): it calls `release` and then `init` while the first `prepare` waits for the toast prefab. It asserts four things:
    - the stopped `prepare` returns `false` with no log
    - the new init stays `_PREPARE_NONE` with no toast prefab
    - a toast request before the new `prepare` is ignored, with one error log
    - a new `prepare` succeeds
  - Mutation check: I removed each session check of `message_core.gd` in turn and ran `test_prepare.gd`, then put the file back with `git checkout`. Every mutation made the new tests fail:
    - without the check at line 114: the module that was released or initialized again got a state other than `_PREPARE_NONE`, so all four tests failed
    - without line 387: a script error reading `enter_tween` on `null`, and in the init-again test `_toast_prefab` was not `null`
    - without line 392: a script error reading `enter_tween` on `null`

  - With the code unchanged, all of them pass
