## spec proposals

- A run whose `init` failed: the spec says a run sends `PUT /started` "when the engine is up and before its first test". A run whose `init` failed has no first test, and the spec does not say whether it sends `PUT /started`. I made it send `PUT /started` before its result, so the tool does not count it as a run that did not start (in a native run, that would add a second failure, "did not start"; in a browser run, the page would be opened again). Proposal: in `### run and result file` of `unit-test-core`, state that a run whose `init` failed also sends `PUT /started`, before its result
- A failed `PUT /started` is logged before `LogCore` is initialized and before any log collector is installed. So its error log is only printed to the engine output (DEV code prints every log line). It is not a run failure in the result, and the run goes on to its tests. The tool then ends the run as not started at `UnitTestCore.startTimeLimitMs`. If the spec wants the run itself to stop, or to record a run failure, it needs to say so
