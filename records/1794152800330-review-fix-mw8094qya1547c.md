It sets `ranking.topCacheMs` to 10000 and caches `GetRankingTop` (board `[rk_sum]`, offset 0, limit 10) holding both users. Then it runs `remove_user` on the same instance and asserts that the same query, at the cache time and at `topCacheMs` - 1 ms after it, holds only the remaining user. Restored defect check: with `core.top_cache.clear()` removed from the `after_commit` callback of server/core/ranking/index.ts:89-91, this test failed on both SQLite and PostgreSQL (job mw80aurk34da02) and the other tests passed. The code was then restored
- R2-2: fixed. Added test `a GetRankingTop that another server instance cached before the removal no longer holds that user topCacheMs after it was cached` (server/core/ranking/tests/withdrawal.test.ts:62). A peer instance (`start_peer`) caches the query holding both users at `cached_at`. `remove_user` then runs on the test server's instance, which itself returns only the remaining user. The peer is read again at `cached_at + topCacheMs/2`, with its result not asserted, since the spec only says it "may" still hold the user. At `cached_at + topCacheMs` the peer's result is asserted to hold only the remaining user. Restored defect check: with a cache hit refreshing `expires_at` (server/core/ranking/query.ts:134), this test failed on both SQLite and PostgreSQL (job mw80b76ia8b3b7) and the other tests passed. The code was then restored
