# review fix: logging round 2

## done

- server module `logging`: `Metrics.alerts` (`server/core/logging/metrics.ts:212`) no longer calls `#prune` and drops no slot. It takes the slots from `#head` at or before the cutoff away from a copy of `#totals`, without moving `#head`. This costs O(slots at or before the cutoff), and the next `line` drops those slots (`#slot` → `#prune`). So a judgement after the test clock went back, following a judgement at a later time, still counts the lines in its window
- Core tests:
  - `server/core/logging/tests/metrics-window.test.ts:144` repeats the review reproduction on `Metrics`: window 100, `alert_error_log_count` 1, one `error` line at 1001, `alerts(1050)` true, `alerts(2000)` false, `alerts(1050)` true again, plus the boundary checks `alerts(1100)` true and `alerts(1101)` false
  - The randomized comparison (`metrics-window.test.ts:103`) runs lines and judgements on separate clocks. About half of the judgements fall between the latest line time and the latest judgement time, so they go back after a later judgement, and the test asserts more than 50 of them. Each judgement is compared with the counts taken from every line written. The two random generators moved into helpers (`judgement_time`, `random_line`) to clear the lint complexity limit, with the same call order
  - `server/core/logging/tests/metrics.test.ts:255` covers the public API: `write` an `error` line, `read_metrics` gives `error_logs` 1; the test clock moves on 2 × `logging.alertWindowMs` and it gives 0; the clock moves back to half a window after the line and it gives 1 again
- With HEAD's `metrics.ts` (prune in `alerts`) restored in this worktree, all three tests failed on sqlite and on postgresql (`ogw core test server logging --file ...`). With the fix all three pass
- The last `ogw core test server` covered `logging` and every server module that `ogw core dependents logging` lists (36 modules), and all passed. After it, `ogw code check core` passed every check: type check, lint, dependency, secret
- No engine-specific implementation rules document was written, and `## <engine> build` of `tools/ogw.md` was not written

## spec proposals

- Carried over from the out-of-scope item of review round 2 (not changed here): `### alert signal` does not say what a judgement counts after the test clock went back past lines that a later line already dropped (`#slot` prunes at each line's time, `server/core/logging/metrics.ts:159`). Recommendation: state that the alert window is the lines written later than the judgement time − `logging.alertWindowMs` that are still kept, where the lines at or before (latest line time − `logging.alertWindowMs`) are not kept. Keeping every line has no bound on memory. This matters only on the test clock
