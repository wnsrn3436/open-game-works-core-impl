## spec proposals

- `after_item_change` returning a value: the item-ledger spec names only a throw of either hook and a bad `validate_item_change` output as hook failures. The code also treats an `after_item_change` return value other than none as a hook failure (core `## hook`: "its output format is wrong"), and with this change that also calls `fail_transaction`. Proposal: name it in the hook failure line of `## hook` of item-ledger
- A core module call with no `source` (`ITEM_CHANGE_SOURCE_UNSPECIFIED`) is handled as the `Recovery`/`Overflow` misuse (throws, no log). The spec does not mention it. Proposal: add it to the `Recovery`/`Overflow` row of `## error`
- `once_key` rows written before this change hold the raw `once_key`, so after an upgrade they no longer match step 2: a change repeated with an old key would be applied again until `onceKeyRetentionMs` passes. The spec has no migration rule for this. Proposal: decide whether a core schema migration rewrites existing rows to the hash form, or whether the change is allowed because no PROD build exists yet
