## unverified

- While reproducing R1-6 I found that on SQLite, the hold-based tests of server/core/friend/tests/lock-timeout.test.ts never reach friend. The holder of `testing.hold_game_row_lock` holds the whole database, so the request fails earlier, at routing's rate counter transaction (`error` log `rate counter transaction failed`, request `INTERNAL`). On SQLite those tests check only that routing fails and that nothing changes. The new spy-based test at lock-timeout.test.ts:83 covers the friend lock failure path on both databases, and the hold-based tests assert the friend `error` log on PostgreSQL, where the request does reach the friend lock. That PostgreSQL assertion passed in the last run
