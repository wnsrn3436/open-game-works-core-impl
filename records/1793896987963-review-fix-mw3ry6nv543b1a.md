## spec proposals

- `### base table` has no index column, so the base table indexes (`ix_game_state_expires_at`, `ix_user_change_next_attempt_at`, and now the two `(contract_version, user_id)` indexes of core schema version 3) are not in the spec. Proposal: write the base table indexes in the `### base table` table, by the same rule as `register_table` index lists ("for each query that cannot select rows with only a leading part of the key column list"), so that a review can check `scan_users` against it
- Error table row "DB connection failure | ... While running, `FAILED` of the operation that opened a transaction" does not say that it covers only statements of that transaction. The implementation now throws for a `read_db` `connection` failure inside a transaction function (rows at storage.md:348 and :353). Proposal: write "a DB connection failure of a statement of that transaction" in that row
