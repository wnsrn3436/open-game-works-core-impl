# ShortcutCore review fix round 3

## done

- ShortcutCore (godot): stage 7 of `navigate` now goes back to the root item when content code pushed another item with the root panel key above it (stack R, A, R). `_close_to_root` (client/godot/core/shortcut_core/shortcut_core.gd:142) calls `UICore.close_panels_to(root key)`. Then, while the stack bottom is a root key item and other items sit above it, it calls `UICore.close_panel` when the top item has the root key and `UICore.close_panels_to(root key)` otherwise, until only the root item is left. On a normal stack it makes the single `close_panels_to` call as before, so the call order and the call count of the spec tests do not change. Any failure, or a session change caused by `release`, stops the stage with `false`
- No engine-specific implementation rules document was written. `## <engine> build` of `tools/ogw.md` was not written
- `ogw core test godot ShortcutCore` pass, `ogw core test godot ShortcutCore --web` pass (`ogw core dependents ShortcutCore` lists only ShortcutCore), `ogw code check core` pass

## spec proposals

- shortcut-core.md stage 7 says only "Calls `UICore.close_panels_to` with that root panel key and waits". That call alone cannot give the stage 9 stack (`panels` on top of the root item) when content code pushed a root key item above the root item, because the `close_panels_to` destination is the topmost item with that key (ui-core.md:184). Proposal: add to stage 7 "When the stack bottom is a root panel key item and items remain above it, calls `UICore.close_panel` while the current panel has the root panel key and `UICore.close_panels_to` with that key otherwise, and waits each time, until only the root item is left. Stops on `false`", plus a `## test` item: "With the stack root R, A, R, B, R, `navigate` with a `Root` shortcut whose `panels` is C ends with R, C, and with `panels` only R or empty, it ends with R". An alternative is a UICore way to close to the root item, which would avoid briefly showing the in-between panels (A in R, A, R)
