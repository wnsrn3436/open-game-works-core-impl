# update core QACore: frame interval and feedback switch

## done

- `QACore` (Godot), commit `dc96094d`:
  - `### frame interval`: the core node reads the frame point with `Time.get_ticks_usec()` first in its `SceneTree.process_frame` method, before device input goes in (`qa_core_node.gd` `on_process_frame`). `init` sizes a `PackedInt64Array` ring to `QACore.frameIntervalMaxCount` with `resize()`. Each later frame point puts its interval in without allocating, and replaces the oldest when the ring is full (`qa_core.gd` `_record_frame_point`). The interval that ends at the first frame point after `AppForegroundReturnedEvent` is left out. `get_stats` writes `frame_intervals_ms` (oldest first, ms rounded half up to 0.01 ms, at most two decimals) and then empties the record. The first open of an automation channel connection also empties it. Emptying keeps the last frame point. `release` deletes the record.
  - `### feedback switch`: the built-in setup commands `set_feedback_off` and `set_reward_presentation_off` (`on`/`off`; any other value is `ok` = `false` and changes nothing). The reward window opens at a `Goal` mark, a `Reward` mark or an `ItemChange` that `rewards` records. A new reward moment keeps it open from that moment. It closes at the first frame start at which `QACore.rewardPresentationWindowMs` advanced ms (telemetry time) have passed since the last reward moment, or when `set_reward_presentation_off`(`off`) runs. The module states follow the spec table and are set only when they change: `SoundCoreDev.set_dev_mute` on `Sfx` and `Ui`, `SoundCoreDev.set_play_skip`, `CameraCoreDev.set_shake_skip`, `ScreenEffectCoreDev.set_world_skip`, `PoolCoreDev.set_effect_skip`, `TweenCoreDev.set_finite_skip`. Turning feedback off on calls `CameraCore.stop_shake`. A module outside the module list is left out. `release` turns both switches and every module state off.
  - `QACore.frameIntervalMaxCount` and `QACore.rewardPresentationWindowMs` are read at `init` with a least value of 1.
  - Tests: new `tests/test_frame_interval.gd` and `tests/test_feedback_switch.gd`. New test resource `resources/qa_effect.tscn` (an auto-return pool effect) with `support/qa_pool_effect.gd`. `test_commands.gd` has the two new commands in the built-in command table. `test_setup.gd` checks the `frame_intervals_ms` field.
- No engine-specific implementation rules document written. `## <engine> build` of `tools/ogw.md` not written.
- Test runs: `ogw core test godot QACore BootstrapCore UnitTestCore` passed, then `ogw core test godot QACore BootstrapCore UnitTestCore --web` passed (the last run). `ogw code check core`: type check, lint, dependency and secret all pass.

## unverified

- "Putting intervals into a full record allocates no memory": the test checks only that the record keeps its size of `QACore.frameIntervalMaxCount` after 20 frames into a ring of 8. No allocation was measured.
- The test of the first `get_stats` of an automation channel connection runs only natively. Browser runs have no listen socket, like the other channel tests.
- The QACore tests check the module states through what each module does: engine bus mute of `Sfx` and `Ui`, the invalid handle of `SoundCore.play`, and no event from `CameraCore.shake`, a `World` fade, an auto-return `PoolCore.borrow` and a tween of repeat count 1. They do not check these parts of the `## test` items, which each module's own tests cover:
  - a content positional player is silent
  - a skipped tween ends at its end state
  - the effect is taken back before the frame is drawn
- The case of an `ItemChange` request made in another callback of the same `ItemChangedEvent` is not tested. The spec leaves that order unset.
