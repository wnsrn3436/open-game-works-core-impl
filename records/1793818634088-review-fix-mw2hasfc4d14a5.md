  - `release` puts the saved text scale (`_settings.text_scale_permille`) back on `LocalizationCore` when `AccessibilityCoreDev.set_test_text_scale` applied a test value (`_test_text_scale_applied`, set by the DEV operation, reset by `_reset_state`). ## spec proposals

- R1-2 (spec change yes, not fixed): settle the text scale right after `AccessibilityCore.release` in the spec. The implementation follows `## DEV` line 142 ("On `release` it returns to the saved value") only for a test value of `set_test_text_scale`, which does not contradict line 83 because `AccessibilityCore` is released before `LocalizationCore`, whose `release` sets 1000. Proposed wording for `## DEV`: "On `release` of AccessibilityCore, a test text scale is replaced on `LocalizationCore` by the saved text scale (the applied option value); the `release` of `LocalizationCore` then sets 1000." Proposed `## test` item: "After `set_text_scale`(1250), `set_test_text_scale`(1500) and `release`, `LocalizationCore.get_text_scale` is 1250." Also state which value "saved value" is when `apply_saved_settings` was not called (the implementation uses the current option value, the default 1000, not the device file value, since before `apply_saved_settings` the settings are not applied)
- R1-4: the spec has no rule for how a core test replaces an engine capability query; the module uses a module-private static `_test_rendering_method` like `TimeCore._test_monotonic_ms`. No public API was added
