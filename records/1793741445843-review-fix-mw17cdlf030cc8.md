## spec proposals

R2-2 and R2-4 have `spec change` `yes`, so they were not fixed. `client/godot/core/realtime_core/realtime_core.gd:1051` is unchanged. They still need a human decision on `client-core/modules/realtime-core.md:183`.

- R2-2: `Open` ends a host's `join_match` only after the host received room updated with `Matching` for that `join_match`. An earlier `Open` only changes `RoomInfo`. Evidence: the server changes the room to `Matching` only after member rating resolution, so an `Open` before that does not mean the party entry ended. Without this change, `ROOM_FAILED`(`BANNED`) at a host `MATCH_REQUEST` still gives `Cancelled` instead of `Failed` with `BANNED`, and a member change that crosses the `MATCH_REQUEST` still loses the match.
- R2-4: state in that line that it covers the `Matching` started with `join_match`, that a host in the `Matching` started with `start_room` stays `Matching`, and add a `## test` item. Evidence: `ROOM_START` never changes the room to `Matching`, so `Open` during `start_room` is an ordinary room change.

These are the same as proposals 1, 2 and 3 of `records/1793740336127-update-core-mw16olbz96f38a.md`.
