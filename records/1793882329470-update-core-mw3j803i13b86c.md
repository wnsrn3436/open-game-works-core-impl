- `client/godot/core/realtime_core/p2p_realtime_transport.gd`
  - `PEER_REJOINED` of an index that is not closed and has had no `connect_peer` in the match, or none since its last peer lost, throws away the `PEER_SIGNAL`s collected for that index and starts no connection. ## spec proposals

- A connection that fails before it ever connects (for example an ICE failure) now raises no peer lost and stays "being made". Nothing restarts it until `PEER_REJOINED`, a rejoined success or a larger offer comes, so in `Connecting` it ends at the connect time limit, and in `Playing` a `Disconnected` participant ends at the reconnect time limit. Before this change, the old code raised peer lost here and RealtimeCore called `connect_peer` again. If a retry is wanted, the spec would need to add this case to the peer lost causes at line 97. Recommendation: keep the current text, because a retry on the same network usually fails the same way, but say so explicitly in the peer lost row
