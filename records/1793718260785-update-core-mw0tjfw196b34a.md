# update core: LocalizationCore

## done

- `LocalizationCore` (godot, commit bfc7127). `_restore_heading_types` (`client/godot/core/localization_core/localization_core.gd:713`) no longer calls `Theme.remove_type`. A heading type the theme did not have before the first `load_fonts` has its base type and font item cleared, so the type variations of the theme based on it keep their base and draw with the heading font after the next `load_fonts`.
- Cause, reproduced with the new core test on the code before the fix: after `release`, `get_type_variation_base` of a style based on `HeadingLabel`, `HeadingButton` or `HeadingRichTextLabel` was empty, and after a second `init` and `load_fonts` the style drew with the default font (width of `A` 60 instead of 92, no weight 800 instead of 800). The style's own font size of 76 stayed.
- New core test for the `## test` item of the spec: `test_a_style_the_theme_bases_on_a_heading_type_draws_with_the_heading_font_after_a_restart` in `client/godot/core/localization_core/tests/test_font_weight.gd`. It covers all three heading types and also holds a font size the style declares.
- Two existing assertions changed in the same file, in `test_heading_text_style_elements_draw_with_the_heading_font_and_release_puts_the_default_font_back` and `test_second_load_fonts_applies_the_weights_again`. They asserted that the heading type is not in `Theme.get_type_list()`, which only `remove_type` gives. The first now asserts an empty base type and no font item, and the second an empty base type, as the Godot rules say. After `release` a heading type the theme did not have stays in `get_type_list()` as an empty record. The next `load_fonts` saves it as a type with no base and no font item, and the next `release` gives the same result.
- `ogw core test godot` and `ogw core test godot --web` pass for `LocalizationCore` and every module of `ogw core dependents LocalizationCore` (26 client modules, no server module). `ogw code check core` passes (type check, lint, dependency, secret).
