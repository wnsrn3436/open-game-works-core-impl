## spec proposals

- R1-3 (`spec change: yes`, not fixed): stage 7 calls `UICore.close_panels_to(root_key)`, and its destination is the topmost item with that key. When the stack holds a second item with the root panel key above the root item (e.g. r,a,r from a `Top` row whose `panels` contains the root panel, or a `Root` row with `panels` R, B), stage 9 does not match the `### navigate order` stack rule of shortcut-core.md (r,a,r + `root_c` gives r,a,r,c and not r,c). Proposal, pick one:
  1. Give `UICore` an operation that goes back to the root item (the bottom item that `open_root_panel` opened) rather than to the topmost item with a key, and have stage 7 call it
  2. Add a data check to `## data` of shortcut-core.md: an element of `panels` that equals the root panel key of `scene` is `out_of_range` ERROR, except when `stack` is `Root` and `panels` is only the root panel key. This does not cover a second root-key item opened outside ShortcutCore, so option 1 is the recommendation
