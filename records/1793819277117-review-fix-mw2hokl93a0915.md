# review fix RemoteConfigCore round 1

## done

- `RemoteConfigCore` (Godot): `test_getters_do_not_allocate` in `client/godot/core/remote_config_core/tests/test_values.gd` now also checks the static memory peak. Before the measured 1000 reads, a `PackedByteArray` ballast raises `MEMORY_STATIC` to `MEMORY_STATIC_MAX`. Any allocation inside the loop then raises `MEMORY_STATIC_MAX`, even one freed before the loop ends. The ballast is freed before the leftover checks run. The documented checks of `OBJECT_COUNT` and `MEMORY_STATIC` are kept, and the test asserts `MEMORY_STATIC > 0` so that a build without memory tracking cannot pass it by default
- No implementation code changed. No engine-specific implementation rules document was written, and `## <engine> build` of `tools/ogw.md` was not written
- `ogw core test godot RemoteConfigCore` and `ogw core test godot RemoteConfigCore --web` passed (`ogw core dependents RemoteConfigCore` lists only RemoteConfigCore). `ogw code check core` passed

## spec proposals

- `client-core/engines/godot.md` (the paragraph "Test of an operation that the spec says does not allocate memory"): replace "catches only allocations that the operation leaves behind" with the peak measurement used here. Make a `PackedByteArray` local before the warm-up, because its array object stays until the function ends. After the first reads, `resize` it to `MEMORY_STATIC_MAX − MEMORY_STATIC + 1`, read `MEMORY_STATIC_MAX`, run the 1000 calls, and read `MEMORY_STATIC_MAX` again. Then `clear()` it and read the two current-value monitors. The test passes when the peak did not grow either. Evidence: on Godot 4.7.2 headless and in the Web DEV export, the clean getters pass. With a temporary `("a" + str(key_id))` or `RefCounted.new()` added to `get_int`, the test fails on the peak assert alone, and the two current-value asserts still pass. The other no-allocation tests (e.g. `pool_core/tests/test_memory.gd`, `input_core/tests/test_memory.gd`, `virtual_pad_core/tests/test_memory.gd`) still use only the current-value method and miss transient allocations in the same way
