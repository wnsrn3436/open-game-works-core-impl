## review

- out of scope (`scene_core.gd:665`, node removed or freed by a stage 4 hiding handler): fixed, see `## done` (`scene_core.gd:663`, `:684`; tests `test_scene_holder.gd:172`, `:176`)
- R2-1: not fixed, `spec change: yes` (see `## spec proposals`)
- R1-2: not fixed, `spec change: yes` on the input line (see `## spec proposals`, the line is stale)
- R1-1: disputed as a code-only finding. The finding is real, but `spec change: no` is wrong. The reviewer's round 4 evidence says "It is closed by the spec decision of R2-1". The measurement in `## spec proposals` shows two things. Godot gives SceneCore no signal when another node's `process_mode` changes. A mode given in the `_process` of one node takes effect for a later node in the same frame. So a mode given between two callbacks of other nodes cannot be stopped by any polling check. Writing to the node itself at every point where scene code can run is not possible either. Each earlier round only moved this gap (round 3 `## review`). It is left as it is until R2-1 is settled
- R2-2: disputed as a code-only finding. The reviewer's round 4 evidence says "Closing it without the per-frame check needs the spec decision of R2-1". The current spec asks SceneCore to stop modes given at any time. It writes no node property, and the engine sends no change signal (see `## spec proposals`). So each check must read the mode of every node under the holder: the cost is linear by necessity, not by choice. The part code alone can do was done in round 2: the check runs only from stage 4 until stage 7, and it reads `_watched` rather than walking the tree. Point 3 of the R2-1 proposal removes the check
