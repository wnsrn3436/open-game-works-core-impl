# open-game-works-core-impl

[한국어](README.ko.md)

The core of open-game-works: the Godot client core, the TypeScript server core, the base protobuf, and the contract and data tools that every game made with the harness is built on.

Games made with it: see the [harness README](https://github.com/wnsrn3436/open-game-works-core).

## What it is

In [open-game-works](https://github.com/wnsrn3436/open-game-works-core), features that many games would rebuild the same way are built once, in advance, as **core**. Agents write only the gameplay, as **content code**, on top of it.

| area | examples |
|---|---|
| infra | server requests and save, login, network and realtime, update, UI, input, platform, dev and test tools |
| live ops | maintenance, notice, kill switch, item grant, ban, coupon, live event, remote config, push |
| store policy | receipts and refunds, terms, age check, account deletion, probability disclosure, tracking permission |
| meta system | item, shop, mailbox, mission, attendance, gacha, ranking, rating, friend, guild |

This repository is the implementation of that core. It is developed through the harness and released as GitHub Releases of this repository; each game pins one release with `coreVersion` in its `settings.json`.

## Status

Under active development, like the rest of open-game-works. See the [harness README](https://github.com/wnsrn3436/open-game-works-core#status) for details.

## How it works

```
open-game-works-core (harness)          module specs: skills/{client,server}-core/modules/*.md
        |  ogw core spec, core agents implement, ogw core test, review agents
        v
open-game-works-core-impl (this repo)   client/godot/, server/core/, tools/, core-spec/
        |  ogw core release <version>   -> tag v<version>, GitHub Release
        v
games/<game>/                           settings.json "coreVersion": "<version>"
        client/core/, server/core/      <- copied from the release by ogw generate
```

- **Spec first.** A module's spec in the harness changes before its implementation; `core-spec/` is generated from the specs.
- **Core does not depend on content code.** Content code passes only hooks, callbacks and data to core; core tells it about things through events.
- **One version for everything.** Client core, server core, both tools and core settings share one core version.
- **Core settings.** Defaults are in [`settings/core-settings.json`](settings/core-settings.json) (e.g. `NetworkCore.retryCount`); a game overrides them in the `core` object of its game settings.
- **Games do not edit core.** When core falls short, the content agent writes a core proposal in the game's `records/core-proposals/`, and a human has it applied with `update core`.

## Repository layout

| path | contents |
|---|---|
| `client/godot/` | Godot client core (itself a Godot project), one module per `core/<module folder>/` |
| `client/godot/plugins/` | core's own native plugins (`ogw-native-ui`, `ogw-secure-storage`): source and prebuilt `dist/` |
| `server/core/` | TypeScript server core, one folder per module, plus the entry point `start.ts` |
| `proto/ogw/` | base protobuf: `core.proto`, `options.proto` |
| `tools/` | `contract-tool/` and `data-tool/` (npm packages) and their round-trip tests |
| `core-spec/` | one JSON file per module, generated by `ogw core spec`; never edited by hand |
| `settings/` | core settings defaults and their JSON schema |
| `fixtures/`, `test-data/` | core test fixtures, and core test data in the structure of a game repo |
| `benchmark/godot/` | benchmark game, released as `benchmark-godot.zip` |
| `records/` | run records of harness commands on this repository |
| `licenses.json` | license manifest of the third-party components that go into the client |

[`client/godot/engine.json`](client/godot/engine.json) pins the engine (Godot `4.7.2.stable`), GUT for tests, the native plugins and the build tools per platform.

## Development and releases

Core is changed only through the harness: a human gives a command in a Claude Code or Codex session opened in the harness folder, and agents do the work.

- `update core: <proposal>` applies a core proposal or a human's request: the module specs change first, core agents implement, review agents check, and a new version is released.
- `create client core: <engine>` makes the client core of a new engine in `client/<engine>/` from the specs and releases it.
- `ogw core release <version>` checks the release conditions (tests, reviews, code checks, `core-spec/` up to date), tags `v<version>` on main and publishes the GitHub Release with its assets and a `manifest.json` of their SHA-256 hashes.
- Versions are `<major>.<minor>.<patch>`. Published assets never change; a fix is a new version.
- A game names its version in `coreVersion`; the harness tool fetches that release, checks it by hash, and `ogw generate` copies it into the game.

<details><summary>Requirements and setup for core development</summary>

Requirements: everything the [harness](https://github.com/wnsrn3436/open-game-works-core) requires, plus:

- Godot at the version in `client/godot/engine.json` (`update env` installs it).
- The harness settings `tools` that core tests and code checks use: `tools.postgresql`, `tools.chromium`, `tools.gdtoolkit`.
- Push access to this repository, for publishing a release.
- A Mac with Xcode, SCons, JDK 17 and the Android SDK, for rebuilding the native plugins; `ogw-secure-storage` also needs MinGW-w64 and Docker. macOS is the primary host.

Setup: clone this repository next to the harness (the harness finds it through `paths.coreImpl` in its `settings.json`), then follow the [quick start](https://github.com/wnsrn3436/open-game-works-core#quick-start) of the harness README. While developing core, harness settings `useLocalCore: true` makes the harness tool use this folder instead of a release.

```sh
cd <workspace>
git clone https://github.com/wnsrn3436/open-game-works-core.git
git clone https://github.com/wnsrn3436/open-game-works-core-impl.git
```

## Contributing

Contributions are welcome. Help is wanted most on:

- Client cores for other engines. Godot is the only one so far; the harness lists Three.js, Phaser, Unity and Unreal as targets.
- Real adapters for store payments, ads, push and social login. They have not been tried against the live services yet.
- The `build` command on Windows, Android and iOS. No game has been built or deployed yet.
- The [resource-making skill](https://github.com/wnsrn3436/open-game-works-core/tree/main/skills/resource) of the harness: generating final art, sound and other resources.
- Games made with open-game-works, and reports of where core fell short.

How to contribute:
- Questions and ideas go to the harness [Discussions](https://github.com/wnsrn3436/open-game-works-core/discussions), core bugs to [Issues](https://github.com/wnsrn3436/open-game-works-core-impl/issues). For a larger change, open one first.
- A behavior change starts as a spec change in the harness (`update core`; a new engine is `create client core: <engine>`).
- A change passes `ogw core test` for the modules it touches and `ogw code check core`.
- Code identifiers and commit messages are written in English.
