# open-game-works-core-impl

[한국어](README.ko.md)

The core of open-game-works: the Godot client core, the TypeScript server core, the base protobuf, and the contract and data tools that every game made with the harness is built on.

Games made with this core are listed in the [harness README](https://github.com/wnsrn3436/open-game-works-core).

## What it is

In [open-game-works](https://github.com/wnsrn3436/open-game-works-core), features that many games would otherwise rebuild the same way each time are built once, in advance, as **core**. Agents write only the gameplay, as **content code**, on top of the core.

| area | examples |
|---|---|
| infra | server requests and save, login, network and realtime, update, UI, input, platform, dev and test tools |
| live ops | maintenance, notice, kill switch, item grant, ban, coupon, live event, remote config, push |
| store policy | receipts and refunds, terms, age check, account deletion, probability disclosure, tracking permission |
| meta system | item, shop, mailbox, mission, attendance, gacha, ranking, rating, friend, guild |

This repository is the implementation of the core. It is developed through the harness and released as GitHub Releases of this repository, and each game pins one release with `coreVersion` in its `settings.json`.

## Status

Under active development, like the rest of open-game-works. See the [harness README](https://github.com/wnsrn3436/open-game-works-core#status) for details.

## How it works

```
open-game-works-core (harness)          module specs: skills/{client,server}-core/modules/*.md
        |  ogw core spec, core agents implement, ogw core test, review agents
        v
open-game-works-core-impl (this repo)   client/godot/, server/core/, tools/, core-spec/
        |  ogw core release <version>   -> tag v<version>, GitHub Release
        v
games/<game>/                           settings.json "coreVersion": "<version>"
        client/core/, server/core/      <- copied from the release by ogw generate
```

- **Spec first.** The module specs in the harness change first, and the implementation changes after them. `core-spec/` is generated from the specs.
- **Core does not depend on content code.** Content code passes only hooks, callbacks and data to core, and core sends events for anything it needs to report.
- **One version.** Client core, server core, both tools and core settings share one core version.
- **Core settings.** Defaults are in [`settings/core-settings.json`](settings/core-settings.json) (e.g. `NetworkCore.retryCount`), and a game overrides them in the `core` object of its game settings.
- **Games do not edit core.** When core falls short, the content agent writes a core proposal in the game's `records/core-proposals/`, and a human uses `update core` to have it applied.

## Repository layout

| path | contents |
|---|---|
| `client/godot/` | Godot client core (the folder itself is a Godot project), one module per `core/<module folder>/` |
| `client/godot/plugins/` | native plugins that core writes itself (`ogw-native-ui`, `ogw-secure-storage`): source and prebuilt `dist/` |
| `server/core/` | TypeScript server core, one folder per module, plus the entry point `start.ts` |
| `proto/ogw/` | base protobuf: `core.proto`, `options.proto` |
| `tools/` | `contract-tool/` and `data-tool/` (npm packages) and the round-trip tests of both tools |
| `core-spec/` | one JSON file per module, generated by `ogw core spec`; not edited by hand |
| `settings/` | core settings defaults and their JSON schema |
| `fixtures/`, `test-data/` | core test fixtures, and core test data in the structure of a game repository |
| `benchmark/godot/` | benchmark game, released as `benchmark-godot.zip` |
| `records/` | records of harness commands run on this repository |
| `licenses.json` | license list of the third-party components that go into the client |

[`client/godot/engine.json`](client/godot/engine.json) pins the engine (Godot `4.7.2.stable`), GUT for tests, the native plugins and the build tools per platform.

## Development and releases

Core changes only through the harness. A human opens a Claude Code or Codex session in the harness folder and gives a command, and agents do the work.

- `update core: <proposal>` applies a core proposal or a human's request. The module specs are edited first; core agents then implement the change and review agents check it before a new version is released.
- `create client core: <engine>` makes the client core of a new engine in `client/<engine>/` from the specs and releases it.
- `ogw core release <version>` checks the release conditions (tests, reviews, code checks, an up-to-date `core-spec/`), tags `v<version>` on main, and publishes the GitHub Release with its assets and a `manifest.json` of their SHA-256 hashes.
- The version format is `<major>.<minor>.<patch>`. Published assets do not change, and a fix comes out as a new version.
- A game writes its version in `coreVersion`. The harness tool fetches that release and checks it by hash, and `ogw generate` copies it into the game.

### Requirements and setup for core development

Requirements: everything the [harness](https://github.com/wnsrn3436/open-game-works-core) requires, plus the following.

- Godot at the version in `client/godot/engine.json` (`update env` installs it).
- The harness settings `tools` that core tests and code checks use: `tools.postgresql`, `tools.chromium`, `tools.gdtoolkit`.
- Push access to this repository, for publishing releases.
- To rebuild a native plugin, the tools listed at the top of that plugin's `build.sh` under `client/godot/plugins/`. macOS is the primary host.

Setup: clone this repository next to the harness and follow the [quick start](https://github.com/wnsrn3436/open-game-works-core#quick-start) in the harness README. The harness finds this folder through `paths.coreImpl` in its `settings.json`. While you develop core, setting `useLocalCore` in the harness settings to `true` makes the harness tool use this folder instead of a release.

```sh
cd <workspace>
git clone https://github.com/wnsrn3436/open-game-works-core.git
git clone https://github.com/wnsrn3436/open-game-works-core-impl.git
```

## Contributing

Contributions are welcome. Help is needed most in the following areas.

- Client cores for other engines. Godot is the only one so far, and the harness lists Three.js, Phaser, Unity and Unreal as target engines.
- Real adapters for store payments, ads, push and social login. They have not been connected to the real services yet.
- The `build` command for Windows, Android and iOS. No game has been built or deployed yet.
- The [resource-making skill](https://github.com/wnsrn3436/open-game-works-core/tree/main/skills/resource) of the harness: generating resources such as final art and sound.
- Games made with open-game-works, and reports of where core fell short.

How to contribute:
- Post questions and ideas in the harness [Discussions](https://github.com/wnsrn3436/open-game-works-core/discussions), and core bugs in [Issues](https://github.com/wnsrn3436/open-game-works-core-impl/issues). For a large change, open one first.
- A change that alters behavior starts from a spec change in the harness (`update core`, or `create client core: <engine>` for a new engine).
- A change must pass `ogw core test` for the modules it touches and `ogw code check core`.
- Code identifiers and commit messages are written in English.
